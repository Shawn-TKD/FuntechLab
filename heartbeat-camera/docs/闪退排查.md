# heartbeat-camera · 闪退排查记录

> 2026-09-22 首次真机安装（APK 构建于 17:22）后**启动即闪退**。
> 本文记录定位过程、两处确定性根因、修复方式，以及后续再遇到闪退时怎么自助取证。

---

## 一、现场条件（决定了排查方式）

| 条件 | 状态 | 影响 |
|---|---|---|
| 手机是否连 adb | **否**（`adb devices` 列表为空） | 拿不到 logcat，只能靠**静态代码分析**定位 |
| 安装的 APK | 构建时间 `17:22:11` | 早于修复时间 `17:45`/`17:46`，**没包含修复** |
| 崩溃时机 | 冷启动、界面都没出来 | 指向 `onCreate` 之前 / 期间抛异常 |

**关键推论**：界面都没渲染就闪退 ⇒ 崩溃发生在 `Application.onCreate`、
`Activity` 构造期或 `onCreate` 早期，**而不是**业务逻辑（连接相机、扫描蓝牙那些）。

## 二、根因 1（最致命）：Activity 构造期调用 `getSystemService`

### 错误代码

```kotlin
class MainActivity : AppCompatActivity() {
    private val orchestrator = HeartbeatOrchestrator(this)   // ❌
}
```

### 为什么会崩

Kotlin 的**属性初始化器在类构造期执行**，而 `Activity` 的构造期**早于** `attach()` /
`onCreate()`。此时 `Context` 还没绑定系统服务，任何 `getSystemService()` 都会抛：

```
java.lang.IllegalStateException:
  System services not available to Activities before onCreate()
```

调用链（全都在构造期被触发）：

```
MainActivity.<init>
  └─ HeartbeatOrchestrator(this)
       ├─ HeartRateMonitor(context)    → 本身不取服务，暂不崩
       ├─ HeartRateScanner(context)    → getSystemService(BLUETOOTH_SERVICE)  ← 💥
       └─ CameraController(context)    → 构造期不取服务（wlan0NetworkId 是懒调用）
```

`HeartRateScanner` 的构造期取值就是压死骆驼的最后一根稻草。

### 修复

```kotlin
private lateinit var orchestrator: HeartbeatOrchestrator

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_main)
    orchestrator = HeartbeatOrchestrator(this)   // ✅ 此时 getSystemService 才可用
    ...
}
```

> **教训**：`Activity` / `Fragment` 里凡是构造期就要 `Context` 的东西（尤其
> `getSystemService`、`Resources` 以外的系统能力），一律 `lateinit` + 在 `onCreate` 里初始化。
> 这条同样适用于 `ViewModel` 之外的自建 controller 类。

## 三、根因 2：Android 12+ 权限未授予时访问蓝牙

### 错误代码

```kotlin
private val bluetoothManager = context.getSystemService(Context.BLUETOOTH_SERVICE) as BluetoothManager
private val scanner = bluetoothManager.adapter?.bluetoothLeScanner   // ❌ 构造期求值
```

### 为什么会崩

Android 12（API 31）起引入「附近的设备」运行时权限：

| 调用 | 需要的权限 |
|---|---|
| `BluetoothManager.getAdapter()` | `BLUETOOTH_CONNECT` |
| `BluetoothAdapter.getBluetoothLeScanner()` | `BLUETOOTH_SCAN` |

而 `HeartbeatOrchestrator` 是在 `onCreate` 里构造的，**那时权限对话框还没弹**。
权限未授予时这些调用会抛 `SecurityException`。

### 修复（`HeartRateScanner.kt`）

```kotlin
// 惰性求值：真正用到时才取
private val bluetoothManager: BluetoothManager by lazy {
    context.getSystemService(Context.BLUETOOTH_SERVICE) as BluetoothManager
}

// 每次访问都容错，取不到就返回 null，由调用方给出友好提示
private val scanner: BluetoothLeScanner?
    get() = runCatching { bluetoothManager.adapter?.bluetoothLeScanner }.getOrNull()
```

`start()` 里也全部改为容错访问，失败时**回调错误而不是崩溃**：

```kotlin
val adapter = runCatching { bluetoothManager.adapter }.getOrNull()
if (adapter == null) { listener.onScanError("设备不支持蓝牙"); return }
if (runCatching { adapter.isEnabled }.getOrDefault(false).not()) {
    listener.onScanError("蓝牙未开启"); return
}
val s = scanner ?: run {
    listener.onScanError("无法获取 BLE 扫描器（请确认已授予「附近的设备」权限）"); return
}
```

## 四、加固措施（本次一并做的）

### 4.1 崩溃自动落盘（`CrashLogger`）

真机没有 adb 时，闪退等于「黑盒」。新增 `CrashLogger.kt`，
把未捕获异常堆栈写入：

```
/sdcard/Android/data/com.insta360.heartbeat/files/crash.txt
```

**不需要 root、不需要数据线**，用手机自带「文件管理」App 就能打开。
写入全部包在 `runCatching` 里，保证「记录崩溃」本身不会再引发崩溃。

同时在 `MainActivity` 启动时读回上次崩溃记录，把**末尾 12 行**显示在界面日志区，
一眼就能看到崩溃点。

> 需要 `BuildConfig.APPLICATION_ID` / `VERSION_NAME`，因此 `app/build.gradle.kts` 里
> 打开了 `buildFeatures { buildConfig = true }`（AGP 8 起默认关闭）。

### 4.2 `onDestroy` 空指针保护

`onCreate` 若中途失败，`orchestrator` 可能仍是未初始化状态，`onDestroy` 再调
`cleanup()` 会抛 `UninitializedPropertyAccessException`，**把真实崩溃原因盖掉**。

```kotlin
override fun onDestroy() {
    super.onDestroy()
    if (::orchestrator.isInitialized) {
        runCatching { orchestrator.cleanup() }
    }
}
```

## 五、下次再闪退怎么办（自助取证）

1. 装新包，打开，复现闪退。
2. 打开手机「文件管理」→ 内部存储 → `Android/data/com.insta360.heartbeat/files/` →
   打开 `crash.txt`。
3. 把内容发出来即可精确定位。

**若 `Android/data` 在文件管理器里被隐藏**（部分 ROM 会藏）：
- 用「MT 管理器」等第三方文件管理器；
- 或**重新打开 App**——启动时界面日志区会直接显示上次崩溃的末尾 12 行。

## 三、⚠️ SDK 2.1.5 真实 API 签名（关键！）

**这一节是本次构建最大的坑来源。** 官方 demo 把这些调用藏在 `ViewModel` + `viewModelScope` 里，
所以从 demo 源码里"看起来"是普通函数 + 回调式 `.onSuccess{}`；实际上**它们是 suspend 函数**。

用 `javap` 从 aar 里反查 `classes.jar` 得到的权威签名：

```java
// CameraDevice
Object connect(connectHint: Any?, Continuation<Result<Unit>>)   // suspend
Object connectWiFi(int, Continuation<Result<Unit>>)             // suspend
Object connectUsb(Continuation<Result<Unit>>)                   // suspend
Object connectBle(BluetoothDevice, boolean, Continuation<...>)  // suspend
void   release()                                                // 普通函数（含断连语义）
boolean isConnected()                                           // 普通函数

// CameraSystem
Object activeCamera(String appId, String secretKey, Continuation<Result<Unit>>)  // suspend

// CameraParam<T>
Object setValue(T, Continuation<Result<Unit>>)   // suspend
Object getValue(Continuation<Result<T>>)         // suspend

// CameraCapture
Object startCapture(GpsInfo?, Continuation<Unit>)   // suspend，返回 Unit（不是 Result！）
Object stopCapture(GpsInfo?, Continuation<Unit>)    // suspend，返回 Unit
Object isWorking(Continuation<Boolean>)             // suspend
void   registerCaptureStatusListener(CaptureStatusListener)  // 普通函数
```

**`CaptureStatusListener` 必须实现全部 8 个方法**（少一个就 "is not abstract and does not implement abstract members"）：

```kotlin
onCaptureStarting(functionMode)
onCaptureWorking(functionMode)
onCaptureStopping(functionMode)
onCaptureFinish(functionMode, filePaths: List<String>)
onCaptureError(functionMode, throwable: Throwable)
onCaptureTimeChanged(functionMode, captureTime: Long)
onCaptureCountChanged(functionMode, captureCount: Int)
onCaptureSubStatusChanged(functionMode, subStatus: CameraCaptureStatus.SubStatus)
```

### 怎么自己查 API（以后遇到不确定的调用）

```powershell
# 1. aar 在 gradle 缓存里
#    E:\gradle_home\caches\modules-2\files-2.1\com.arashivision.sdk\<模块>\<版本>\<hash>\*.aar
# 2. 解 aar 拿 classes.jar（注意 aar 里还有一层 jar）
# 3. 用 javap 看签名
& "E:\2026智能影像挑战赛\_buildenv\jdk\jdk-17.0.2\bin\javap.exe" -classpath classes.jar `
  com.arashivision.sdk.camera.api.CameraCapture
```

> 名称里带 `-0E7RQCE` / `-IoAF18A` / `-gIAlu-s` 后缀的，都是 Kotlin **suspend 函数**的 JVM 擦除痕迹
> （`Continuation` 参数被 value class 内联了）。看到这类后缀就知道是 suspend。

### 因此本工程引入的协程依赖

`app/build.gradle.kts` 加了 `kotlinx-coroutines-android:1.9.0`；
`CameraController` 内部持有一个 `CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)`，
所有 suspend 调用都用 `scope.launch { ... }` 包起来。`NanProcessNetworkBinding` 也从
"回调 + Handler" 改成了 `suspend fun awaitDefaultNetwork(context)`。

## 四、踩坑清单（都已修复，改代码时注意别回退）

### 坑 1：AGP 拒绝含中文的项目路径
```
Your project path contains non-ASCII characters. This will most likely cause the build to fail on Windows.
```
工程在 `E:\2026智能影像挑战赛\`（"智能影像挑战赛"是中文）。
**修**：`gradle.properties` 加
```properties
android.overridePathCheck=true
```
本工程**没有 native 源码需要编译**（影石 SDK 是预编译 aar，`.so` 直接打包），
所以关掉这个路径检查是安全的。

### 坑 2：Manifest 合并冲突（application@label）
```
Attribute application@label value=(心跳控制相机) is also present at
[com.arashivision.sdk:onestream:2.0.20] AndroidManifest.xml value=(@string/app_name)
```
影石 SDK 的 `onestream` 模块自带 `<application android:label="@string/app_name">`。
**修**：`AndroidManifest.xml` 根标签加 `xmlns:tools="http://schemas.android.com/tools"`，
`<application>` 上加 `tools:replace="android:label"`。

### 坑 3：Gradle build-cache 写入被拒
```
Failed to store cache entry ... for EnumerateClassesTransform:
...\caches\build-cache-1\xxx.part (拒绝访问。)
```
Windows 上 `.part` 临时文件被文件锁/安全软件占用。
**修**：`gradle.properties` 设
```properties
org.gradle.caching=false
```
（关掉 build cache，只损失一点增量速度，构建稳定性优先。）

### 坑 4：SDK 方法是 suspend 函数
见上文第三节。**修**：引入协程 + 用 `scope.launch` 包调用。

### 坑 5：`BluetoothLeScanner.startScan` 两参重载没了
```
None of the following candidates is applicable:
  fun startScan(p0: ScanCallback!): Unit
  fun startScan(p0: List<ScanFilter!>!, p1: ScanSettings!, p2: ScanCallback!): Unit
  fun startScan(p0: List<ScanFilter!>?, p1: ScanSettings?, p2: PendingIntent): Int
```
API 31+ 移除了 `startScan(ScanSettings, ScanCallback)`。
**修**（`HeartRateScanner.kt`）：
```kotlin
s.startScan(emptyList<ScanFilter>(), settings, callback)
```

### 坑 6：⭐ APK 出现 235MB 巨型体积（假象，最阴的一个）
现象：APK 文件 235MB，但用 zip 工具看内容只占 36MB。
诊断：解析 zip 中央目录，算「中央目录偏移」与「最大引用数据末端」的差值 —— 发现 **180MB 未引用空洞**。

原因：前一次构建（那时还依赖 `sdk-media`，含 135MB 的 `libarvbmg.so`）的产物残留在
`app/build/intermediates` 里，`packageDebug` 复用了旧的 zip 骨架但没正确重写整个文件。

**修**：`gradle clean` 后重建 → **33.7MB**。
**结论：改完依赖或发现 APK 体积异常时，一定先 `clean`。**

### 坑 7：本机 PowerShell stdout 经常被吞
命令成功（exit 0）但拿不到任何输出。**习惯做法：把结果 `Set-Content` 写文件，再用 Read 工具读。**
另外本机 `Add-Content` 不支持 `-FilePath`（要用 `-Path` 或 `Out-File -Append`）；
bash 工具在本机不可用（`dirname` / `head` / `ls` 全部 not found）。

### 坑 8：⭐ 真机启动即闪退 —— Activity 构造期调 `getSystemService`
```kotlin
private val orchestrator = HeartbeatOrchestrator(this)   // ❌ 构造期执行
```
Kotlin 属性初始化器在**类构造期**跑，早于 `attach()` / `onCreate()`，此时取系统服务会抛
`IllegalStateException: System services not available to Activities before onCreate()`。
调用链：`MainActivity.<init>` → `HeartbeatOrchestrator` → `HeartRateScanner` → `getSystemService(BLUETOOTH_SERVICE)`。

**修**：改 `private lateinit var orchestrator`，在 `onCreate` 里（`setContentView` 之后）初始化。
**规律**：Activity/Fragment 里凡构造期就要 `Context` 系统能力的字段，一律 `lateinit` + `onCreate` 初始化。

### 坑 9：⭐ Android 12+ 权限未授予时访问蓝牙 → `SecurityException`
`BluetoothManager.getAdapter()` 需 `BLUETOOTH_CONNECT`；`BluetoothAdapter.getBluetoothLeScanner()` 需 `BLUETOOTH_SCAN`。
而 orchestrator 在 `onCreate` 构造，那时权限对话框还没弹。

**修**：`HeartRateScanner` 的 `bluetoothManager` 改 `by lazy`，`scanner` 改容错 getter：
```kotlin
private val bluetoothManager: BluetoothManager by lazy {
    context.getSystemService(Context.BLUETOOTH_SERVICE) as BluetoothManager
}
private val scanner: BluetoothLeScanner?
    get() = runCatching { bluetoothManager.adapter?.bluetoothLeScanner }.getOrNull()
```
`start()` 里也全部 `runCatching`，失败走 `onScanError` 回调而不是崩。

### 坑 10：真机无 adb 时闪退取证
见 `docs/闪退排查.md`。要点：新增 `CrashLogger` 把堆栈写到
`/sdcard/Android/data/com.insta360.heartbeat/files/crash.txt`（文件管理器可直接打开，无需 root/数据线），
并在 `MainActivity` 启动时把上次崩溃末尾 12 行显示在界面日志区。
> 需要 `BuildConfig`，故 `app/build.gradle.kts` 打开 `buildFeatures { buildConfig = true }`（AGP 8 默认关闭）。

## 五、APK 瘦身决策：移除 sdk-media

原依赖是 `sdk-camera` + `sdk-media`。实测 `sdk-media` 传递引入：

| 原生库 | 大小 | 来源 |
|---|---|---|
| `libarvbmg.so` | **135.3MB** | `bmgmedia-2.901.3.3.aar` |
| `libarffmpeg.so` | 13.1MB | 同上 |
| `libarypto.so` | 3.6MB | 同上 |
| 合计 | **≈155MB** | |

而本工程只做「实时触发拍摄」，**从不调用媒体 SDK 的任何功能**
（`InstaMediaSDK` 只在 `HeartbeatApp` 里 `init` 过一次）。

**修**：`app/build.gradle.kts` 移除 `implementation(libs.inskmp.media)`，
`HeartbeatApp` 删掉 `InstaMediaSDK.init(this)`。APK 从 ~190MB → **33.7MB**。

> 去掉 `sdk-media` 后 `sdk-camera` 自身只剩 7 个 `.so` 共约 4MB
> （`libc++_shared` 1.2MB、`libinssocket` 0.89MB、`libinsusb` 0.73MB 等）。
>
> **如果以后要加"事后把相机里的视频同步到手机"**，需要重新加回 `libs.inskmp.media`
> 并恢复 `InstaMediaSDK.init`（参考 `docs/方案说明.md` 第 5 节）。那时 APK 回到 ~190MB 属正常。

## 七、装到手机

1. 把 `app-debug.apk` 传到手机（微信/QQ 发文件、USB 拷、网盘都行）。
2. 手机文件管理器里点它安装。若被拦：
   - 小米/红米 MIUI：设置 → 更多设置 → 开发者选项 → 打开 **USB 安装**；
   - 或安装时按提示允许"安装未知应用"。
3. 打开 App，**全部权限都要给**（蓝牙、定位、通知）—— 少一个 SDK 不初始化。
4. 然后按 `README.md` 第六节走：连 GO Ultra 热点 → 连接 → 填激活码 → 激活 → 开模拟心率试链路。

> 首次安装是全新包名，**不会覆盖**官方 Insta360 App，两者可共存。

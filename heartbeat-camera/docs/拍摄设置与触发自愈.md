# 拍摄设置可手改 + 触发链路自愈（v10）

> 起因：用户反馈两点 ——
> ①「拍摄设置不要把心率范围和延时拍照的时间定死了，要能手动改，改完按新参数跑」；
> ②「拍摄设置修改后，就心率变化也不会操作相机了」。

---

## 一、根因：触发失败后**不回滚**，引擎永久卡在 REC

### 真机日志铁证

```
23:00:48.215 D/HeartbeatOrchestrator: hr=111 state=REC action=START mode=VIDEO
23:00:48.218 I/HeartbeatUI: >> 触发录像                     ← 界面已经宣布"开拍"
23:00:48.254 I/CameraController: ⚠ 无法开拍：相机未连接。     ← 36ms 之后才知道失败
23:00:48.753 D/HeartbeatOrchestrator: hr=111 state=REC action=NONE
23:00:49.028 D/HeartbeatOrchestrator: hr=112 state=REC action=NONE
...（心率 118/120/122 持续）state=REC action=NONE
```

### 出了什么事

`ThresholdEngine` 是**迟滞状态机**：

```
PAUSED --心率 ≥ onThreshold--> 返回 START，状态切 REC
REC    --心率 <  offThreshold--> 返回 STOP，  状态切 PAUSED
其余            -> 返回 NONE
```

`START` 是**边沿触发**的 —— 只在「从 PAUSED 跨到 REC 那一次」返回。

而旧代码在收到 `START` 时**无条件**做了两件事：

```kotlin
ThresholdEngine.Action.START -> {
    callback?.onCameraTriggered(true)   // ① 先告诉界面"开拍了"
    camera.startRecord()                // ② 再问相机（返回值被丢掉）
}
```

如果 ② 失败了（相机没连 / 模式切换被拒），**状态机已经在 REC 了**。
之后心率哪怕一直在 120，状态机也只返回 `NONE`，**再也不会重发 START**。

结论：一次失败 = 这段时间内彻底瘫痪，直到心率掉到停止阈值以下再上来一次。
用户看到的就是——**「心率变化，但相机完全没反应」**。

### 两个附带缺陷

1. **界面说假话**：`onCameraTriggered(true)` 在相机确认之前就发出去了。
   日志里 `>> 触发录像` 比 `无法开拍：相机未连接` **早 36ms** ——
   用户看到界面写「已开拍」，实际根本没开。这一条之前以为修过，实际没落盘。
2. **相机连接状态变了也不重试**：因为 ①，没有任何"再试一次"的路径。

---

## 二、修法：先问相机，失败就回滚

```kotlin
ThresholdEngine.Action.START -> {
    if (camera.startRecord()) {
        callback?.onCameraTriggered(true)   // 只有相机接受了才通知界面
    } else {
        engine.reset()                      // 回滚 → 下一次心率上报继续尝试
    }
}
```

`engine.reset()` 把状态打回 `PAUSED`。心率此刻仍 ≥ 开拍阈值，
所以**下一拍心率上报（最迟 1 秒后）会重新走一次 START**。

效果：
- 相机没连上时，每秒都会重试一次，**相机一连上就自动开拍**，不用等心率回落；
- 界面只在真正开拍后才写「已开拍」，不再误导排查。

### 异步阶段的失败也要回滚

`startRecord()` 的同步前置检查（device != null 且已连接）能返回 Boolean，
但**真正的 SDK 调用是 suspend 的**，等它返回时调用方早走了。
所以 `CameraController.Listener` 新增了：

```kotlin
/** 开始命令在「异步阶段」最终失败了（模式切换被拒 / startCapture 被拒）。 */
fun onStartFailed(reason: String)
```

编排层收到就 `engine.reset()`，给回滚补上最后一块。

## 三、`armed` 与 `capturing`：两个「在拍」状态必须分开

| 字段 | 含义 | 谁设置 |
|---|---|---|
| `armed` | **心率触发的拍摄会话开着**（= 心率高于阈值这段时间） | App 主动设置 |
| `capturing` | **相机自报正在拍摄** | 相机状态回调 |

依据官方 demo（`CameraCaptureViewModel` 注释）：
**间隔拍照 / 星轨 / 延时在两次快门之间 `isWorking()` 返回 false，`capturing` 也跟着抖。**

早期只有 `capturing` 一个标志，导致两个真机问题：

1. 间隔拍照两张之间 `capturing=false`，被误判成「没在拍」；
2. 停止时若 `capturing=false` 且 `isWorking()=false` 就直接**跳过停止命令**，
   于是「界面显示已暂停、相机还在按节拍拍」。

**改后规则：「这次采集开没开」只认 `armed`，`capturing` 仅用于界面展示和防命令堆叠。**

---

## 四、间隔秒数不再被固件合法值「定死」

GO Ultra 固件的 `lapse_time` 只接受离散值（`go_ultra.json` 实证：`[0,1,3,5,10,30,60,120]` 秒）。
用户想填 7 秒怎么办？两条路自动二选一：

| 路径 | 触发条件 | 实现 | 特点 |
|---|---|---|---|
| **3a 固件原生** | 填的值在合法值里 | `PHOTO_INTERVAL` + 设 `lapse_time`，一次 `startCapture()` | 相机自己按节拍：最准、最省电 |
| **3b App 定时器** | 填的值**不在**合法值里 | `PHOTO_NORMAL`（单张拍照）+ App 协程每 N 秒 `startCapture()` | 秒数完全自由，代价是每次快门一次 WiFi 往返 |

3b 的实现要点：

```kotlin
while (isActive && armed) {
    if (capturing) { delay(200); continue }   // 上一张没拍完，等它，别把命令堆一起
    dev.capture.startCapture()
    delay(secs * 1000L)
}
```

- 循环条件带 `armed` → 心率回落时自动停；
- 相机连续报「忙」超过 10 秒就强制继续，防止状态回调丢失导致永久卡住。

## 五、取值范围的硬限制放开

| 参数 | 旧 | 新 | 说明 |
|---|---|---|---|
| 开拍 / 停止阈值 | 40~220 bpm | **30~250 bpm** | 只是防手滑的兜底，不是产品限制 |
| 间隔秒数 | 1~120 秒（且被吸附到固件合法值） | **1~600 秒，任意值** | 非固件合法值走 3b |

另外两条体验修正：

- **间隔输入框不再按模式置灰**。旧版在录像模式下 `isEnabled=false` + 半透明，
  用户看到的就是「延时拍照的时间被定死了」——现在任何时候都能填，
  只是录像模式下不生效（摘要行会写明「仅『间隔拍照』模式生效」）。
- **被兜底调整时不再静默改数**。填 999 保存成 250 会在日志区明说
  「开拍阈值 999 → 250（有效范围 30~250 bpm）」。
  停止阈值 ≥ 开拍阈值仍会被压成「开拍 − 1」（迟滞不变量必须保），但同样会明说原因。

## 六、改完设置如何「立即按新参数跑」

```kotlin
fun saveSettings(...): AppSettings.Saved {
    val wasRecording = engine.state == REC
    val saved = settings.save(on, off, interval, mode)
    if (wasRecording) camera.stopRecord()   // 参数是下发到相机的，不重开就还按旧参数拍
    applySettingsToEngine()                 // 新模式/新间隔灌进 camera
    engine.reset()                          // 复位 → 下一拍心率用新参数自动重开
    return saved
}
```

不用手动再点一次「启动」，也不用等心率回落再上来一次。

## 七、复测要点

1. 相机**不连**的情况下启动心率，日志应每秒重试、只报一次
   「⚠ 无法开拍：相机未连接」（去重，不刷屏）；**界面上不应出现「触发录像」**。
2. 此时再点「连接 GO Ultra」→ **心率仍高于阈值时应当自动开拍**（不用等回落）。
3. 改阈值（例如开拍 100 / 停止 95）→ 保存。心率若已高于 100，**立即**应看到
   「▶ 开始命令下发中…」并开拍。
4. 间隔填 7 秒（非固件合法值）→ 日志应出现
   「ℹ 相机不支持「每 7s」这个间隔（支持：…），改用 App 定时器实现」，
   随后每 7 秒一条「📷 已触发第 N 张」。
5. 间隔填 10 秒（固件合法值）→ 日志应出现「✅ 间隔已设为 10 s（相机固件执行）」。

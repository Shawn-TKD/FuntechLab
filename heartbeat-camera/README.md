# heartbeat-camera ⚡ 用心跳自动控制 Insta360 GO Ultra 拍摄

> 面向小白的分步操作手册。目标是：**心率一超阈值就自动开拍（录像 / 间隔拍照可选），心率一回落就自动停。**

配套进度说明与方案见 `docs/方案说明.md`。

---

## 一、整个工程是干嘛的（3 句话）

1. 手机**订阅 BLE 心率的实时广播**（Garmin FR255 开的「心率广播」，或随时可用的模拟心率）。
2. 一个**迟滞阈值引擎**：心率 ≥ 开拍阈值 → 开拍；心率 < 停止阈值 → 停（默认 110/100，10 拍回差防抖，**阈值可在 App 上改**）。
3. 调用 **Insta360 GO Ultra 的 SDK**：`startCapture()` / `stopCapture()`，由固件真正拍。

```
心率源(Garmin/模拟) --BLE→ 手机App:阈值引擎 --WiFi→ GO Ultra 录像 / 间隔拍照
```

**两种拍摄模式（App 上选）：**

| 模式 | 行为 | 底层 |
|---|---|---|
| **录像** | 心率超阈值 → 开始录像；回落 → 停止 | `FunctionMode.VIDEO_NORMAL` |
| **间隔拍照** | 心率超阈值 → 每 N 秒自动拍一张；回落 → 停止 | 见下方两条路径 |

**间隔拍照的两种实现（按你填的秒数自动二选一，**任意秒数都支持**）：**

| 路径 | 何时走 | 实现 | 特点 |
|---|---|---|---|
| 固件原生 | 你填的秒数**在**相机合法值里 | `PHOTO_INTERVAL` + `lapse_time`，一次 `startCapture()` | 相机自己按节拍：最准、最省电 |
| App 定时器 | 你填的秒数**不在**合法值里 | `PHOTO_NORMAL`（单张拍照）+ App 每 N 秒触发一次 | 秒数完全自由，代价是每次快门一次 WiFi 往返 |

> GO Ultra 固件的 `lapse_time` 只接受**离散值：0 / 1 / 3 / 5 / 10 / 30 / 60 / 120 秒**
> （`assets/insta/json/params/go_ultra.json` 实证）。
> 但**间隔秒数不会被这张表限制死** —— 你填 7 秒，程序自动改走 App 定时器照常每 7 秒拍一张，
> 并在日志里说明「相机不支持 7s，改用 App 定时器」。

## 六、怎么连 GO Ultra 并开始自动拍（联调顺序）

**准备：** GO Ultra 开机，进入 WiFi 热点模式，手机系统 WiFi 连上相机的热点（记下 SSID/密码）。

**App 操作顺序：**
1. **启动前**：手机已连上 GO Ultra 的 WiFi。
2. 打开 App → 在「**拍摄设置**」区选好模式（录像 / 间隔拍照）、填好阈值和间隔 → 点 **保存设置**。
3. 点 **连接 GO Ultra（WiFi 直连）**。日志显示「相机已连接」。
4. 填激活码 → **激活相机** → 日志「激活成功」。
5. 心率源就位后，点 **启动模拟心率**（或接真实 Garmin）。

跑起来后：模拟心率冲过开拍阈值时，日志会打 `>> 触发录像`（或 `>> 触发间隔拍照`），GO Ultra 开始拍；
回落到停止阈值以下时打 `>> 停止录像`（或 `>> 停止间隔拍照`）。

## 六·五、拍摄设置怎么用（阈值 / 间隔 / 模式）

「**— 拍摄设置 —**」区三件事：

| 控件 | 作用 | 可填范围 |
|---|---|---|
| **拍摄模式**（录像 / 间隔拍照） | 决定心率超阈值后是持续录像，还是每 N 秒拍一张 | 二选一 |
| **开拍阈值 bpm** | 心率 **≥** 此值开始拍 | **30 ~ 250** |
| **停止阈值 bpm** | 心率 **<** 此值停止拍 | 30 ~ 250，且**必须小于开拍阈值** |
| **间隔 秒** | 间隔拍照的拍照间隔 | **1 ~ 600，任意整秒都支持** |

**几个要点：**

- **全部可手改，改完点「保存设置」即按新参数跑**，不需要重启、也不用等心率回落再上来一次。
- **没有"定死"这一说**：
  - 阈值范围放到 30~250 bpm（只是防手滑，不是产品限制）；
  - 间隔秒数任意填，相机固件不支持的秒数会自动改走 App 定时器（见第一节的两条路径）；
  - **「间隔 秒」输入框任何时候都能编辑**，不再按模式置灰（录像模式下填了不生效，
    摘要行会写明「仅『间隔拍照』模式生效」）。
- **被兜底调整时会明说**，不静默改数：日志区会打
  「⚠ 有数值被有效范围兜底调整：开拍阈值 999 → 250（有效范围 30~250 bpm）」。
- **停止阈值填反了会自动纠正**：若你填的停止阈值 ≥ 开拍阈值（比如都填 110），
  程序会自动把它压成「开拍阈值 − 1」，因为迟滞失效会导致相机在阈值附近疯狂开关。同样会提示原因。
- **设置会持久化**（SharedPreferences），杀掉 App 重开仍是上次的值。
- 底部「**当前生效：**」那一行随时告诉你现在真实生效的是什么，改完立即刷新。
- ⚠️ **拍摄过程中改设置**：程序会先把相机停掉再应用新设置，然后**自动用新参数重新开拍**
  （只在你心率此刻仍高于新开拍阈值时）。所以改设置会中断当前这段拍摄，请在开拍前调好。

## 六·六、素材上传：录完传服务器（v11 新增）

「**— 素材上传 —**」区，**一个按钮**：`上传最新一段（LRV → MP4）`。

点击后自动完成：**列相机素材 → 挑最新一条 `.lrv` → 下载 → 换壳成标准 MP4 → 上传服务器**。
按钮忙碌时文案变成「取消上传」，再点一次即取消（**已下载的文件会留着，下次点按钮只重试上传**）。

| 控件 | 说明 |
|---|---|
| **服务器上传地址** | HTTP POST 地址。默认 `http://127.0.0.1:8000/upload`，配合 `adb reverse` 打到电脑上的测试服务 |
| **上传最新一段（LRV → MP4）** | 一键跑完全流程；忙时变「取消上传」 |

**为什么要用 `.lrv` 而不是主视频**：`.lrv` 是相机给手机端做快速预览的**低码率副本**，
体量小、传得快，适合先把「拍完上云」这条链路跑通。**它的画质明显低于主视频**，
要原画质就改传主文件（见 `docs/素材上传.md` 第二节）。

**三个关键点**（详细原理见 `docs/素材上传.md`）：

- **`.lrv` → `.mp4` 是「换壳」不是「转码」**：LRV 本身已是 H.264/H.265 的 ISO-BMFF 流，
  用 `MediaExtractor` + `MediaMuxer` 把轨道原样搬进新容器 → 秒级、画质无损、不吃 CPU。
- **⚠️ 上传会自动挑对网络出口**：手机连着相机热点时**没有公网**（这是最容易踩的坑）。
  程序检测到默认网络没有联网验证时，会**显式把请求绑到蜂窝数据**上，
  于是「一边连着相机热点、一边用 4G 传视频」是可行的。
- **不引 `sdk-media`**：列文件/下文件用的是 `sdk-camera` 自带的 `CameraDevice.file`，
  APK 体积保持 **34.8MB**（引 sdk-media 会涨到 ~235MB）。

### 端到端测试（不用联网、不用云服务器）

```bash
# 1) 电脑上跑接收服务（只用标准库，不用 pip install）
cd heartbeat-camera/server
python upload_server.py --port 8000 --out "E:\心跳相机上传"

# 2) 开 USB 反向端口转发（手机插着 USB 即可，不要求同一局域网）
D:\AndroidSdk\platform-tools\adb.exe reverse tcp:8000 tcp:8000

# 3) App 里地址保持默认 http://127.0.0.1:8000/upload → 连相机 → 录一段 → 点上传按钮
```

电脑终端会打印 `✓ 已保存 xxx.mp4（xx.xx MB, sha256=…）`。

> 部署到自己服务器只需**改地址**，协议就一个 `POST /upload`（multipart）。
> 字段与注意事项（明文 HTTP / 鉴权 / 备案 / Nginx 体积限制）见 `docs/素材上传.md` 第四节。

## 七、如何接真实 Garmin FR255 心率

### 第 1 步：在 FR255 上开启「心率广播」（必须）

在手表上按 **右上角 LIGHT 键 → 长按 → 设置**，或直接用快捷键：

- **设置 → 传感器及配件 → 腕式心率 → 广播心率** → 选「**开启**」
- 或在**控制菜单**里（表盘界面按 LIGHT 键）找「**心率广播**」快捷开关。

开启后手表会显示一个心率图标，表示正在向外广播。

> ⚠️ FR255 广播心率会**显著耗电**（实测约 2 倍以上），演示完记得关掉。
> 可在「设置 → 传感器及配件 → 腕式心率 → 广播心率」里设为「**活动期间**」自动开关。

### 第 2 步（推荐）：先在系统蓝牙里配对

这一步不是必须，但**强烈建议做**，成功率会高很多：

**手机设置 → 蓝牙 → 搜索 → 选 "Forerunner 255"**，配对成功即可。

> App 扫描时会把**已配对**的设备优先列在列表顶部，直接点它最稳，不用在几十个陌生设备里找。

### 第 3 步：在 App 里点选连接

1. 点 **扫描心率设备（点选列表里的 FR255）**。
2. 稍等 1～2 秒，下方出现设备列表。
   - **带「✔ 广播含心率服务」且显示红色**的，是最硬的证据（广播包里就带了 0x180D），基本可以直接点；
   - 标「★ 最可能」的是当前排序第一的那台；
   - 标「已配对」的是你系统蓝牙里配过的；
   - 每行还显示**信号强度 dBm**——FR255 就戴在你手上，通常是最强的那台。
3. **点你的 FR255 那一行**即可连接。
4. 连上后：
   - 「心率源: 已连接 Forerunner 255（心率订阅中）」；
   - **设备列表自动消失，扫描按钮变成「已连接 Forerunner 255（无需再扫描）」并置灰**；
   - 顶部心率数字开始实时跳动。

> **连上之后为什么不用再扫描了**：设备一旦连上，App 就停掉 BLE 扫描、清空并隐藏设备列表、
> 把扫描按钮锁住。这样既省电，也避免你误点到别的设备把当前连接顶掉。
>
> **什么时候会恢复可扫描**：只有在连接**断开或失败**时，扫描按钮才重新可用
> （比如手表走远了、心率广播关了）。此时列表保持隐藏，你重新点扫描即可。
> 想主动断开，点底部「停止/断开」。

> **为什么不用自动连接**：BLE 扫描**只能拿到设备名和 MAC，拿不到它提供什么服务**，
> 所以扫描阶段无法 100% 判定哪台是心率带。早期版本「自动连第一个」实测会连到耳机或电视上，
> 导致心率永远收不到。现在改为点选（但会用「广播是否含 0x180D」帮你把最可能的排到第一行）。
>
> **列表里几十个陌生设备是正常的**——那是你周围所有开着的蓝牙设备。认准你的手表名即可。

### 如果连上了但心率不动

App 的日志区会明确告诉你卡在哪一步：

| 日志 | 含义 | 怎么办 |
|---|---|---|
| 「连接超时（15s）」 | 根本没连上 | 确认手表开了「心率广播」，且没被别的手机占用 |
| 「这台设备没有心率服务 0x180D（发现的服务: ...）」 | **连错设备了** | 换列表里带 ✔ 的那行重连 |
| 「连接异常(status=133)，正在重试 1/3」 | GATT 脏状态 | 等它自动重试；连败就在系统蓝牙里「取消配对」后重配 |
| 「心率订阅成功，等几秒就会出数」 | 链路已通 | 若仍不动，**把表戴上手腕**——没佩戴时不出心率 |

> FR255 广播的是**标准 BLE 心率服务 0x180D / 特征 0x2A37**，本 App 直接就能读，**不用给手表写任何程序**。
>
> 更完整的排查清单见 `docs/BLE连不上排查.md`。

## 九、常见报错 → 解决办法

| 报错 / 现象 | 原因 | 解决 |
|---|---|---|
| 依赖下载失败(HTTP 401/404) | Maven 凭据没配 / 填错 | 见「四、配置 Maven 凭据」 |
| 激活失败 | 手机没公网 / 激活码错 | 断相机热点开蜂窝，或核对 AppId+SecretKey |
| 「未找到 wlan0 网络」 | 手机没连相机热点 | WiFi 直连前先连 GO Ultra 热点 |
| BLE 扫不到 Garmin | 没开广播 / 需先配对 | 在 FR255 开「心率广播」+ 系统蓝牙先配对 |
| 扫出一堆设备、不知道点哪个 | 正常现象（周围所有蓝牙设备） | 认准列表里**带 ★ 的红色行**或标「已配对」的；见第七节 |
| 连上后心率不动 | 连错设备（那台没有 0x180D 服务） | 日志会提示「未暴露心率服务」，换一台重连 |
| 相机连接失败(冲突/占会话) | 上次没断开 | 点一次「停止/断开」再重连 |
| 选了间隔拍照但间隔没生效 | 填的秒数相机不支持 | 固件的合法值是**运行时问相机**得到的（GO Ultra 为 0/1/3/5/10/30/60/120，GO 3S 为 3/5/10/30/60/120）；不在表里的秒数会自动改走 App 定时器。日志里看「间隔已设为 N s（相机固件执行）」或「改用 App 定时器实现」 |
| **心率明明超阈值，相机却不动作** | 见 `docs/拍摄设置与触发自愈.md` | v10 已修：触发失败后不给引擎回滚 → 引擎永久卡在 REC 再也不重发。现在失败即回滚，**每秒重试，相机一连上就自动开拍**。旧版（≤v9）务必换 |
| 界面写「触发录像」但相机没动 | 旧版先通知界面再问相机 | v10 已修：只有相机接受了才写「触发…」。若还看到，说明装的是旧版 |
| 无法装 APK | MIUI 拦 USB | 开「USB 安装」或文件管理器点装 |
| **打开就闪退** | 见 `docs/闪退排查.md` | 首次真机闪退已修复（Activity 构造期取系统服务 + Android 12 蓝牙权限）。若仍闪退：打开手机文件管理 → `Android/data/com.insta360.heartbeat/files/crash.txt` 看堆栈；或重开 App，日志区会显示上次崩溃末尾几行 |
| **扫描/连手表时界面卡死、弹「无响应」** | 见 `docs/卡死ANR排查.md` | v9 已修：主线程被 BLE 扫描回调洪泛 + 排序里同步调 `BluetoothDevice.getName()` 拖死（真机 ANR 堆栈已证实）。请务必装 v9 及以上 |
| **点上传报「相机未连接」** | 下素材必须走相机 WiFi | 先连相机 WiFi 热点 → 点「连接相机」 |
| **上传失败，日志说「未找到可用公网出口」** | 手机连着相机热点且没有蜂窝数据 | 文件已缓存在手机里：**先断开相机 WiFi**，再点一次上传按钮即续传 |
| **日志「相机素材里没有 .lrv」** | 该固件不落 LRV | 属正常兜底，会自动改传最新 `.mp4`；详见 `docs/素材上传.md` |
| **列素材返回 0 条** | 卡是空的，或固件返回格式与预期不同 | 先录一段；仍为 0 就把日志里那行「📂 相机素材：…」明细发出来 |
| **刚连上的相机突然变「未连接」** | 见 `docs/连接保持与界面重建.md` | v12 已修：Activity 重建时 `onDestroy` 把整条链路拆了（折叠屏折叠/展开、旋转都会触发）。现在编排者是进程级单例，连接保持、界面自动回填 |
| **重连报 `camera connect failed -214`** | 相机会话是独占的，旧会话还占着 | v12 起不会再出现（连接不再被无谓拆掉）；若仍遇到，点一次「停止/断开」再连 |
| **日志反复出现「已取消上传」而你没点过** | 旧版 `release()` 无条件打日志 | v12 已修（只在真的在传时才打）。若是旧版，忽略即可 |

> ⚠️ **adb 在这台手机上只能读日志、不能模拟点击**（MIUI 限制：
> `SecurityException: Injecting input events requires ... INJECT_EVENTS permission`）。
> 若需让电脑端自动操作界面，需在开发者选项里额外打开「**USB 调试（安全设置）**」。

> **无数据线时怎么取证**：本 App 内置了崩溃落盘（`CrashLogger`），把堆栈写到
> `/sdcard/Android/data/com.insta360.heartbeat/files/crash.txt`，
> **不需要 root、不需要 adb**，用手机自带文件管理器就能打开。

## 十一、⚠️ 关于 APK 体积（重要）

本工程**只依赖 `sdk-camera`，不依赖 `sdk-media`**，APK 稳定在 **34.8MB**。

原因：`sdk-media` 会传递引入 `bmgmedia`，带进 `libarvbmg.so`(135MB) + `libarffmpeg.so`(13MB)
等约 **155MB** 原生库（APK 会涨到 ~235MB），而它提供的是 360 全景播放/剪辑/导出能力，本工程用不上。

> **v11 的素材上传也没有引 sdk-media**：列文件 / 下文件用的是 `sdk-camera` 自带的
> `CameraDevice.file`（`CameraFile`），实测签名见 `docs/素材上传.md` 第二节。
> 所以「事后同步相机文件」这条路**不需要**打开 sdk-media 了 —— 这是 v11 相比早期方案的一个修正。

## 十二、⚠️ 代码里的 SDK 调用是 suspend 函数

Insta360 SDK 2.1.5 的 `connect` / `activeCamera` / `param.setValue` / `startCapture` / `stopCapture`
**全部是 Kotlin suspend 函数**，必须在协程里调用（官方 demo 藏在 ViewModel 里所以不明显）。
v11 新增的素材接口同样如此：`CameraDevice.file.listMediaFiles()` / `downloadMediaFile()`
也是 suspend（签名实测见 `docs/素材上传.md`）。

本工程已引入 `kotlinx-coroutines-android`，`CameraController` 与 `upload/ClipUploadManager`
各自持有一个 `CoroutineScope` 统一调度。
改代码时若发现「Suspend function can only be called from a coroutine」这类报错，就是这个原因。
`CaptureStatusListener` 也**必须实现全部 8 个回调方法**，少一个都编译不过。细节见 `docs/构建与踩坑.md`。

| `pip3` | 已预配内网源 `mirrors.cloud.aliyuncs.com/pypi/simple/`，实测下载 whl 成功 | ✅ 可用（约 300 kB/s） |
| `github.com` | HTTP 200，0.89 s | ✅ 通 |
| `mirrors.aliyun.com` | HTTP 301 | ✅ 通 |
| `registry.cn-hangzhou.aliyuncs.com` | HTTP 401（需鉴权 = 服务正常） | ✅ 通 |
| **`registry-1.docker.io`（Docker Hub）** | **10 s 超时，完全不通** | ❌ **拉镜像必须配加速器** |
| `pypi.org` 直连 | 10 s 超时 | ❌ 只能走内网/阿里源 |

### 由此得出的两条硬规则

1. **装 Docker 后第一件事是配镜像加速器**，否则 `docker pull` 全部卡死。
   可用：阿里云 ACR 个人版免费加速地址（控制台 → 容器镜像服务 → 镜像加速器），或直接用 ACR 企业版仓库。
2. **pip 不要用默认的 pypi.org**（本机已配阿里内网源，默认就对）。

## 四、网络与安全边界

| 项 | 实测 |
|---|---|
| 内网 IP | `172.28.190.82/20`，默认路由走 `172.28.191.253` |
| VPC 内网元数据 | `100.100.100.200` 可达（拿到 instance-id / region / 规格） |
| **公网可达端口** | **只有 22**。80 / 443 / 8000 / 8080 / 3306 / 6379 从公网**全部不可达** |
| SSH 配置 | `PermitRootLogin yes`、`PasswordAuthentication yes`、**`authorized_keys` 为空（0 条）** |

### 直接结论

- 想对外提供服务，**必须去阿里云控制台的安全组里放行端口**（这是云侧配置，机器内部改不了）。
- 目前是「root + 密码 + 公网 22」这种最容易被打的组合，且**没配任何密钥**。
  公网 IP 上的 root 密码登录每天会被扫，**强烈建议尽快**：
  1. 生成密钥对 → 把公钥写进 `/root/.ssh/authorized_keys`；
  2. 确认密钥能登 → 改 `PasswordAuthentication no`；
  3. 想更稳就把安全组 22 端口限制到固定来源 IP。
- 这台机器是**杭州地域**。国内地域用域名对外提供 Web 服务需要 **ICP 备案**；
  不备案只能「IP + 非 80/443 端口」访问（测试阶段够用）。

## 五、与项目的匹配度：什么该放上来

| 组件 | 能否部署 | 说明 |
|---|---|---|
| Android App（APK） | ❌ | 客户端，装在手机上 |
| Garmin BLE / 相机 WiFi 直连 | ❌ | 纯本地链路，与服务器无关 |
| **`server/upload_server.py`（素材接收）** | ✅ | 现成的，纯标准库，**可以直接搬上来跑** |
| 接收后的转码 / 抽帧 / 缩略图 | ✅ | 但需先 `apt install ffmpeg`（8 核转码够用） |
| 生图代理服务（Qwen-Image-Edit / z-image / Kolors 的 Key） | ✅ | **推荐做**：Key 放服务端，不进 APK |
| **自建生图模型推理** | ❌ **不可行** | 无 GPU。本机跑扩散模型不现实，只能调 API |
| Web 管理端 / 演示看板 | ✅ | 需要放行安全组端口 |
| 对象存储 / 大文件留存 | ⚠️ | 40 GB 系统盘，见下 |

### ⚠️ 磁盘容量是最需要预算的一项

现场录一段 4K 视频动辄数百 MB ~ 数 GB。**系统盘只剩 34 GB**，如果按「上传即落盘留存」来设计，几次测试就满了。建议：

- 接收后**只保留派生物**（转码 MP4 / 关键帧 / 缩略图 / 元数据入库），原始大文件及时清理或转投 OSS；
- 或单独挂一块数据盘 / 用阿里云 OSS（对象存储），别塞系统盘；
- 顺手加个定时清理任务（`cron` 已在跑）。

## 六、建议的下一步（按优先级）

1. **先配 SSH 密钥、关掉密码登录**（安全债，越早还越省事）。
2. **装 Docker + 配镜像加速器**，把 `upload_server.py` 用容器跑起来。
3. **控制台安全组放行一个测试端口**（如 8000），手机用 4G 直连验证「不依赖 adb reverse」的真实链路。
4. 补 **swap**（2~4 GB），避免内存抖动被 OOM Kill。
5. 再谈业务：接收 → ffmpeg 转码 → 落库 → 对接生图 API。

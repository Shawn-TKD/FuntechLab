# 白日梦想家 Agent：原生音效与克制配乐改造规划

日期：2026-10-02。状态：本地代码已实施，207项自动化测试通过；未发起新的付费生成，未部署线上服务。下文保留设计规划，实际落地差异见末节。

本版替代此前“独立生成音乐与音效，再进行后期混音”的首选方案。采用当前视频模型直接生成画面与声音的路线。用户最新要求：背景音乐克制、可选，进入与退出时机必须符合剧情和氛围。

## 1. 本次目标与声音原则

完整流程为：主题 → 行动脚本 → 视觉风格 → 分镜规划与全片声音方向 → 逐镜画面和声音描述 → 编译视频提示词 → 生成有声视频 → 保留原生音轨完成剪辑与交付。

### 1.1 背景音乐可选，不是完成条件

- 默认不预设全片铺音乐，不要求每镜都有音乐；全片不使用背景音乐是合法结果。
- 先判断环境声和动作音效是否已经足以表达当前经历，只有音乐有明确作用时才使用。
- 配乐跟随已经确定的剧情和氛围，不为了音乐制造新的情节、强行拔高情绪或安排高潮。
- 需要配乐时，用少量乐器、适当留白和较低音量；不能遮盖关键动作音效。
- 不机械规定音乐必须占全片多少比例，不以“每片至少一次”或“最后一定升华”作为模板。
- 纯器乐，无旁白、对白、演唱、吟唱和人声采样；不引入其他人声。

### 1.2 音效以动作和空间为依据

- 关键音效绑定明确的动作，例如轮胎触地、金属卡扣扣合、物体碰撞。
- 环境声描述空间、距离和持续状态，例如风声、机械运转、远处水声。
- 没有发生按铃动作就不添加车铃；不因为“更有氛围”添加无关动作音效。
- 不必给每个动作都添加强调音，不默认使用转场呼啸、重低音冲击或密集提示音。
- 可以保留安静与留白。没有背景音乐不等于完全静音，环境声、动作声仍可存在。

### 1.3 配乐必须回答的四个问题

1. 为什么此处需要音乐？关联哪段已确定剧情或哪种氛围变化？
2. 什么动作或情境出现时进入？在此前明确保持无配乐。
3. 使用什么乐器、疏密、速度和强度？如何给重要音效留出空间？
4. 什么动作或情境出现时退出？退出后明确不再自行恢复。

“营造氛围”“增强沉浸感”不能单独代替进入和退出条件。也不能因为写了音乐方向，就让后续所有镜头自动铺满音乐。

## 2. 在现有哪一步生成声音描述

| 阶段 | 生成内容 | 实现位置 |
|---|---|---|
| 分镜规划 | 全片是否需要配乐、候选剧情节点、统一音色与克制原则、主要环境/动作声音 | `src/daydreamer_agent/story/assembly.py` 的 PLAN_PROMPT |
| 逐镜创作 | 本镜无配乐或局部配乐、进入/退出触发条件、具体乐器与强弱；动作音效与声音延续 | 同文件 SHOT_PROMPT、逐镜上下文 |
| 视频提示词编译 | 合并原有视觉描述、音效、可选配乐及声音限制 | `src/daydreamer_agent/prompts/video_compiler.py` |
| 视频生成 | 根据完整提示词同时生成画面和声音 | 现有 H3 provider |
| 剪辑与交付 | 保留模型原生音轨，校正音视频长度，拼接并导出 | `media/ffmpeg.py`、`application/pipeline.py`、`application/delivery.py` |

声音创作复用现有分镜模型调用，不增加独立的“再写一次声音提示词”调用。保持先确定行动，再描述伴随的声音。

逐镜上下文增加必要的“前镜声音描述”和“下一镜行动范围”，供当前镜判断音乐是否仍有必要延续、何时退出。上下文中不要带入未来不存在的生成音频，也不声称文本知道前镜实际生成了什么旋律。

兼顾 `story/generator.py` 中旧的整包故事路径：它也应读到同样的可选配乐要求，避免只有默认分镜组装路径遵守新规则。

## 3. 数据格式：优先复用已有字段

第一版不扩展 `shot.prompt` 的四个键，也不把 `audio.music` 从字符串改成复杂对象。这样可减少对旧故事、示例、校验和恢复逻辑的影响。

| 现有字段 | 新的明确含义 |
|---|---|
| `audio_plan.music_direction` | 全片配乐取舍和使用边界；允许写“全片不使用背景音乐” |
| `audio_plan.sound_motifs` | 与主题及动作相关的重复声音元素；允许为空数组 |
| `audio_plan.speech_policy` | 仅允许环境声、动作音效和必要的纯器乐配乐，禁止人声 |
| `shot.audio.music` | 非空字符串；本镜无配乐时明确写“本镜不使用背景音乐”；有配乐时写进入、表现、退出和无配乐区间 |
| `shot.audio.sfx` | 与本镜动作/环境匹配的声音描述数组，允许为空 |
| `shot.audio.continuity` | 环境声/动作声如何跨段延续，以及音乐是否延续、进入或结束；不得默认要求音乐连续覆盖 |

非空字段不等于必须有音乐。不要用空字符串或省略字段表示无配乐，防止模型自行补全。

### 3.1 全片不配乐的合法示例

```json
{
  "audio_plan": {
    "music_direction": "全片不使用背景音乐。用轮胎滚动、链条转动和随速度变化的风声表现骑行节奏与空间。",
    "sound_motifs": ["持续的轮胎滚动声", "随骑行速度变化的风声"],
    "speech_policy": "仅环境声和动作音效，无任何人声。"
  }
}
```

### 3.2 单镜局部配乐示例

以下假设该镜剧情已经确定为“骑行穿出狭窄通道，进入开阔路面，随后接近急弯”。这些动作是示例前提，不能由声音提示词新增到真实故事中。

```json
{
  "audio": {
    "music": "穿出狭窄通道之前不使用背景音乐。当开阔路面第一次完整进入视野时，极轻的钢琴单音与薄而柔和的弦乐缓慢进入，音符稀疏，无鼓点，低于车轮声。当我开始减速准备入弯时，音乐逐渐退出；入弯过程中及本镜余下部分只保留环境声和动作声。无演唱、吟唱或人声采样。",
    "sfx": [
      "轮胎滚动和链条转动持续存在，离开通道后声音的短促回响减弱。",
      "开阔路面的风声较通道内明显，随减速逐渐减弱。",
      "实际刹车减速时出现轻微刹车摩擦声，与手部操作和速度变化同步。"
    ],
    "continuity": "前段轮胎与链条声延续进入本镜。音乐只在穿出通道后的短暂开阔段出现，减速准备入弯时退出，不延续到下一镜；风声和轮胎声可随动作继续。"
  }
}
```

这里的音乐写法是有事件边界的局部配乐，不是“保持轻快背景音乐”一类全程铺底指令。

### 3.3 时间表达规则

- 首选可观察的动作锚点，例如“门打开后”“第一次看见开阔空间时”“准备刹车时”。
- 必要时辅以本镜相对时间范围，例如“本镜约 3–5 秒”；避免全片时间与单次生成时间混淆。
- 使用秒数时必须落在本镜时长内；与动作描述不能互相冲突。
- 时间范围是模型生成指令，不是后期样本级排程，不能承诺精确到指定毫秒。
- 第一版不从自由文本中推导可强制执行的时间线，不因此引入独立音频生成或调度模块。

## 4. 最终视频提示词的组装方式

保留现有主题、世界规则、第一人称、视觉风格和连续状态等共享约束，随后输出本镜描述。

```text
【景别】
现有景别描述。

【构图】
现有构图描述。

【运镜手法】
现有运镜描述。

【画面内容】
按顺序描述实际行动。需要同步的关键音效明确绑定相应动作，不能增加新事件。

【音效】
读取本镜 audio.sfx，描述环境底声、关键动作音效和空间层次。
必要时补充 audio.continuity 中的环境声、动作声衔接。

【背景音乐】
无配乐：明确写“本镜不使用背景音乐，仅保留已描述的环境声和动作音效。”
局部配乐：明确此前无音乐、进入触发条件、乐器和强度、退出触发条件，以及退出后的无配乐区间。
有意延续：说明沿用的音色、节奏和强度，以及本镜何时应当退出；不因延续而默认铺满全片。

【声音限制】
背景音乐可选，仅在本镜明确指定的情境或区间出现；其他部分不添加配乐。
音乐克制、稀疏，不能遮盖关键动作音效，不自行添加高潮或煽情收尾。
无旁白、对白、演唱、吟唱、人声采样及其他人声。
```

“无配乐/局部配乐/有意延续”是创作时的三种选择，实际提交只保留适用于本镜的具体描述，不能把三个互斥分支原样一起发给模型。

内部 `shot.prompt` 仍为原四项，最终字符串增加音效与音乐段。不要仅把完整 audio_plan 无差别复制到每镜，否则全片音乐设定可能覆盖本镜的无配乐决定。全片方向作为创作上下文，本镜具体声音决定作为执行指令。

当前百炼 H3 接口接收一个 `input.prompt` 字符串，没有必要新增未经文档支持的 audio 开关。若后续改用 H3 官方三段格式，可把视觉与同步动作对应到 integrated_multimodal_description，环境/动作音效对应到 overall_soundscape，背景音乐对应到 non_diegetic_music。无背景音乐时只有配乐项可写 N/A，不能连带清空需要保留的环境声。

官方依据：[H3 提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)、[百炼 H3 接口](https://help.aliyun.com/zh/model-studio/minimax-video-generation-api-reference)。两种提示词排版是候选表达方式，当前先采用与原项目一致的中文分段格式，并通过样片验证。

## 6. 保留原生音轨需要的具体改动

现有 `Media.prepare_clip()` 与拼接步骤使用 -an，因此仅增加声音提示词仍会在导出前丢掉音轨。配置字段也必须真正被处理代码读取。

### 6.1 三条互斥合成路径

| 路径 | 声音来源 | 合成方式 |
|---|---|---|
| native，新的首选 | 模型生成视频内的原生音轨 | 保留、统一格式、同步裁剪并拼接 |
| manual，兼容现有功能 | 用户明确提供的本地音频清单 | 默认使用清单替换生成音轨，避免重复配乐；保留原有混音功能 |
| off，明确选择 | 无 | 导出清楚标记的无声预览 |

`--audio` 保留既有语义：选择 manual。若同时提供矛盾模式，报清楚的参数错误，不静默叠加两套声音。

native 的主流程可以在技术校验成功后从视频生成进入 composing，再进入 completed；无需新增 audio_planning/audio_generating 状态。

### 6.2 片段准备与拼接

- 视频与原生音频使用同一剪辑起点和目标时长；统一音频采样率/声道，处理编码延迟和允许的短尾差异。
- 图片末帧提取仍只读取视频轨，这一步保留 -an 不影响成片声音。
- 包含必要环境/动作声音却缺失音轨时，明确报错或暂停，不默默用静音填补并宣布成功。
- 有意全静音的片段应有显式、可校验的静音标记：可在生成参数/制作元数据中记录，不从“无背景音乐”文字推断。拼接时可给这种片段补等长静音音轨以统一容器结构。
- “没有背景音乐”通常仍有环境声，不能据此跳过音轨检查。
- 不给每个片段默认做音乐淡入淡出，以免持续风声和动作声在镜头边界周期性变弱。
- 若出现边界爆音，只做必要的极短去点击处理；不能假称它能修复不同旋律或节拍。
- 不自动为没有声音的区间补音乐，不强制整片末尾淡出。

### 6.3 复用和恢复的影响

`prepare_boundary()` 的 prepared_basis 目前包含 preparation_version。更改音轨保留策略时，版本与声音模式必须进入该摘要，不能复用旧的无声 prepared.mp4。

现有后镜依赖包含前镜 prepared_sha256 和 tail_sha256。单纯给前镜保留音轨也会改变 MP4 文件哈希，但未必改变末帧画面。实施时需区分“视觉续接依赖”和“成片音频/容器依赖”：在末帧像素和视觉处理结果不变且有验证证据时，避免仅因音频重封装而重生成后续画面；旧任务保守保留原规则，做版本化兼容，不直接删掉已有依赖检查。

正式成片和准备片段的缓存依据必须包含声音来源与处理版本。completed 状态不能绕过对输出失效的必要判断。

## 7. 旧任务与原始素材

- 新规则应用于新任务；旧任务保留原始冻结配置和已保存的生成请求，不悄悄改写故事或提示词摘要。
- 旧任务若还保留模型下载的 clip.mp4，可先检查它是否有音轨。有音轨时，允许显式选择 native 后重新准备和合成；仍不代表其旧音乐内容符合新的克制配乐要求。
- 旧原片没有音轨时，提示词无法给已有像素文件凭空增加声音。要采用本路线，需显式创建新的生成尝试；或者继续使用已有 manual 功能。
- 若希望旧视频体现新的局部配乐安排，应创建新故事/请求版本后生成，不能原地修改已冻结请求而继续冒用旧结果。
- 保留的是“模型生成视频的音轨”，不是用户上传生活素材的原声音轨。上传素材的语音不直接进入成片。

## 8. 能力边界

H3 支持原生声音生成，官方说明见 [MiniMax H3](https://www.minimax.cn/news/minimax-h3-open-source)。本规划利用该能力，但实际提示词遵循程度需要样片验证。

- 第一人称首帧续接传递画面，不传递前段音频。跨段复用同一配器描述可以约束声音方向，不能保证同一旋律和节拍无缝继续。
- 第一版优先在自然的动作/氛围边界安排短配乐段，但不能为了避开镜头边界而篡改剧情或强行提前结束本应延续的音乐。
- 音效和音乐可能已经混在同一原生音轨里；若音乐过强，单独降低整轨会同时降低音效。当前路线无法保证无损分离和单独换掉配乐；需要时重生成该片段或未来另做专门后期能力。
- “无背景音乐”“进入/退出时机”和“无人声”均是生成约束，不是通过有音轨或文件可解码就能证明满足。
- 保持现有不自动做媒体内容审核的策略。技术检查与样片人工听评分开记录，不能把 has_audio 等同于内容合格。

## 9. 分阶段实施与验证

### 第一阶段：声音创作与最终提示词

工作：修改分镜规划、逐镜创作、旧路径提示和项目内 skill 文档；编译器接入已有 audio 字段；版本化模板。

验证：

1. 全片无配乐故事可正常通过格式检查。
2. 单镜无配乐会明确写入最终提示词，不因全片音乐方向又被覆盖。
3. 局部配乐明确进入前和退出后的无配乐区间。
4. 音效绑定当前镜头动作，声音编译不增加新的剧情。
5. 仍只有原有故事/分镜模型调用，没有额外声音模型调用。
6. 四项视觉字段与原有连续性约束保持一致，最终提示词长度合规。

### 第二阶段：原生音轨保留与主流程接通

工作：实现 native/manual/off；处理音视频同步裁剪、格式统一、拼接和交付；更新恢复与缓存。

验证：

1. 带测试音轨的原片经过 prepared、拼接和最终导出后，目标频率仍可检测。
2. 音效与画面的相对位置不因裁剪和拼接逐段漂移。
3. 无外部音频清单的 native 任务可以正式完成，不再停在 awaiting_audio 或自动转无声预览。
4. 有意无配乐不会被判断为缺失音乐；有意静音与意外缺音轨分开处理。
5. manual 仍去掉原片音轨并使用清单，off 仍产出无声预览。
6. 音频处理策略变化不会复用旧无声缓存，也不会无依据重生成全部后续镜头。

### 第三阶段：代表性样片和网页联调

制作或选取三类测试案例：

| 案例 | 预期声音 |
|---|---|
| 动作本身足够有节奏的骑行段 | 只有轮胎、链条、风声，全段无配乐 |
| 从封闭空间进入开阔空间，再转入需要集中注意的动作 | 开阔节点短暂进入克制音乐，准备关键动作时退出 |
| 连续多段生成 | 检查环境声是否突断，音乐是否被每段自行重启，明确跨段能力限制 |

人工听评关注：音乐是否不必要、进入是否提前、退出是否拖延、音量是否抢过动作声、有无未经要求的结尾高潮或人声。记录偏差并调整提示词，不把所有失败都交给更复杂的后期系统。

网页检查：实际播放新成片、可以打开声音、暂停和关闭时没有残余声音、播放受限时可点击继续。

### 对应测试文件

- 扩展 `tests/test_minimax.py`：正确模型参数、最终声音段及无配乐指令。
- 扩展 `tests/test_seeded.py`、`tests/test_story_timing.py` 或新增少量声音契约用例：无配乐合法、上下文传递、时间描述不改变镜头时长。
- 扩展 `tests/test_media.py`：native 保留音轨、manual 替换、off 静音、同步与片段边界。
- 扩展 `tests/test_pipeline.py`、`tests/test_frame_chain.py`：状态分流、依赖摘要、旧缓存和恢复。
- 扩展 `tests/test_workflow.py`、`tests/test_video_workflow.py`、`tests/test_web_service.py`：选项冻结、导出类型、网页完成结果。

不写“关键词出现即代表音乐克制/剧情契合”的内容合格测试；程序测试验证结构与行为，听感以实际样片记录为准。

## 10. 交付标准

本次改造完成后，应达到：

- 声音描述在原有分镜创作过程中产生并进入最终视频提示词。
- 音乐可以完全不出现，也可以仅在有剧情依据的短区间出现。
- 进入、退出、无配乐区间和声音层次均在本镜指令中明确。
- 模型生成的声音经过剪辑仍保留在最终视频里。
- 有声成片不依赖额外音乐服务、音效服务或本地音频清单。
- 旧任务、手动音频清单、明确的无声预览路径保持可解释的兼容行为。

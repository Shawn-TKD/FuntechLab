# 单方案创作与随机 Seed

一键入口与 plan 创建的新故事任务按主题、连续行动脚本、画风、分镜规划、逐镜生成、程序组装的顺序执行，生成后直接交接，不再调用独立故事复核。每阶段只生成一个方案，不生成候选列表，不做随机挑选，也不与上一作品比较相似度或自动重写。

主题、脚本、画风在最终组装时直接深复制已保存的阶段字段；后续模型只能返回新增字段，不能覆盖它们。规划请求包含已确定内容一次，不附带完整技能文件、所有原始事件字段或错误整包故事。单镜请求携带统一主题与画风、全片动作提纲、当前beat、当前动作范围、相关世界规则和前镜结束状态，不携带其他镜头的完整JSON。

规划按自然动作拆分，程序校验脚本覆盖、顺序、时长与镜数；每镜生成后立即校验并保存。后镜start由程序复制前镜end，start_state/end_state由六项状态生成；引用和编号由程序从已确定关联计算。最后程序补齐schema_version、来源、记忆版本、固定无声语言限制与空checks等字段，并执行本地结构校验。不会调用模型生成内容审阅结论。

规划和单镜使用严格JSON Schema与独立输出预算：8192、4096 token。字段违规或输出截断仅修复当前小结果，完整异常响应仍保留。多个短请求不保证总调用费用一定下降，但减少重复输出与单次长输出风险。正文前三阶段仍使用原有技能输入，保证创作规则和既有检查点兼容。

固定第一人称视点由程序在组装分镜时补齐：先检查prompt四个字段都是非空文字，再为缺少声明的画面内容添加“第一人称视角，摄像机代表经历者的眼睛。”。不改写原始响应或镜头正文，补充记录保存在assembly-record.json的prompt_defaults。这个步骤提供制作约束，不代表语义或实际视频画面已通过第一人称审查。空字段等真实结构问题仍只修正当前镜头，并提供具体字段路径和验收要求。

旧任务若因“每镜画面内容需明确第一人称”耗尽重开次数，首次恢复允许用新规则重新校验本轮缓存一次；保留原失败原因、seed和重开计数，复用已确定主题、脚本和画风，不新增创作轮次。其他错误不适用此迁移。

主题包含持续行动目标 action_goal，core_rule明确行动必要的能力和边界；script按同一目标下的应对和后果推进，不安排反转或套用完整起承转合。按自然动作边界拆镜，不平均分配时长。每镜起止状态和continuity.object_states同时保存目标与行动进展。画风非写实但空间具体可读，不以扁平化、抽象堆叠代替情节。视频编译器2.1传入目标、前镜结果、当前关联beat及本镜动作范围，不传入后续beat；旧故事没有action_goal时以statement兼容。

每个新任务从系统随机源生成一个整数种子，保存在 input/creativity.json。各阶段使用由任务种子和阶段名称派生的整数 seed，作为 Qwen 请求 JSON 顶层参数传入。恢复时复用已保存内容，尚未返回的请求仍使用原种子。种子影响采样，但不保证内容一定不同或服务端逐字复现。

保留原有事件引用、字段、时长与连续状态的本地校验；不做生成后的内容核查或模型自评，checks兼容字段输出空数组。格式错误最多修正一次，修正使用另一派生种子。空内容、非法 JSON 和输出截断会保存原始响应及结束原因；重复恢复不会清空修正次数。网络中断不自动重发请求，可用原任务编号恢复。

某阶段修正次数用尽后，自动使用新 seed 从主题阶段重新开始创作，复用事件卡，保留同一任务编号。默认最多重开2次（包含初次共3轮），设置为 `[story].max_creation_restarts`，范围0–5。仅格式修正耗尽触发此机制；网络错误、鉴权问题、模型拒绝和需要补充素材的状态直接停止。重开计数和新种子在发出请求前保存，中断恢复不重置预算。

记录位置：

- input/creativity.json：任务种子和采样设置。
- story/seeded/responses/：每阶段响应、实际种子、温度、耗时；异常响应也会保存。
- story/seeded/errors/：网络错误原因及耗时。
- story/seeded/assembly-v1/plan.json：分镜与时长规划、声音和记忆文字元数据。
- story/seeded/assembly-v1/shot-001.json：各镜头的独立检查点，编号顺序递增。
- story/seeded/assembly-v1/responses/：规划和单镜原始响应、修正记录、用量和输出预算。
- story/seeded/assembly-v1/assembly-record.json：锁定主题、脚本、画风的摘要校验值与最终故事摘要。
- story/creation-attempts.json：重开上限、每轮种子、失败阶段与结果。
- story/seeded-restart-01/：第一次重开的独立检查点、响应和错误；后续编号递增。初次失败记录仍在story/seeded/。
- outputs/<任务编号>/创作随机种子.json：随成片导出的种子记录。
- outputs/<任务编号>/创作重开记录.json：所有创作轮次及最终实际采用的种子。

旧候选任务首次恢复时，将已选定的主题、脚本等保存到 input/reused-story-stages.json，原配置备份到 input/creativity-before-seed-only.json，原候选文件保持原样。未选定的候选不会继续抽选，后续按单方案生成。已生成的故事与视频继续使用原有检查点。

尚未完成的seed-only任务自动使用新组装接口，前三阶段复用原检查点。旧整包story阶段修正耗尽的任务允许本轮改走新接口一次，保留旧失败原因和总重开次数，不强制丢弃已确定内容；新接口自身失败后仍使用原有重开上限。更早的无seed旧任务保留原生成逻辑。

config/default.toml 的 [creativity] 保留 enabled 与 temperature，默认启用种子记录、温度1.0。Qwen 故事请求等待上限仍为600秒，与视频的5分钟重提规则独立。代码入口为 story/seeded.py、story/assembly.py 与 providers/qwen.py。

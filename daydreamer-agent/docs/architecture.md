# 架构与文件结构

状态：第一版命令行实现已完成；当前验证结果见 [验证记录](validation.md)。

## 1. 范围与已确定要求

- 输入为生活事件卡 JSON，可同时提供故事记忆和本次制作要求。
- `qwen3.8-max` 按 `daydreamer-style-transfer` 完成主题、第一人称脚本、视觉风格、四项分镜及声音方案。
- 先完成情节，再选择视觉风格；历史世界记忆不决定本次画风。
- 首段用 `wan3.0-video-prime`；后段用 `wan3.0-video-prime`，以实际剪辑前段的末帧续接。
- 成片仅包含背景音乐与音效，无旁白、对白、演唱、人声采样及源素材人声音轨。
- 分镜提示词仅有景别、构图、运镜手法、画面内容四项。
- 不做生成后的故事或媒体内容核查；仅保留本地格式、引用、时长、状态契约和文件技术检查。
- 当前提供命令行入口；音乐和音效支持本地清单导入，自动生成音频的服务尚未接入。

## 2. 应用形态与依赖方向

采用一个 Python 应用和一个流程编排器，不在第一版引入多个独立 agent、微服务、消息队列或独立数据库服务。初期通过命令行启动任务，后续界面复用同一应用服务。

流程编排器通过接口调用故事、视频、音频、媒体和存储能力。业务数据契约不依赖某个模型 SDK；平台请求格式与认证封装在 providers 中。

```text
未来的命令行或界面
        ↓
application：任务编排、检查点、恢复
        ↓
domain：统一输入输出与任务状态
        ↓
story / prompts / memory / media / storage
        ↓
providers：百炼及后续音频服务
```

选择本地 JSON 文件保存可审阅的创作产物，SQLite 保存任务和镜头状态、远端任务 ID 与产物索引。视频和音频只保存为文件，不写入数据库。SQLite 文件在首次运行时建立。

## 3. 主流程

1. 创建任务：分配 run_id，保存原始事件卡及本次配置快照，保留输入文件不变。
2. 整理输入：验证 JSON，规范化事件卡，记录来源；缺失事实保留为未知。
3. 读取记忆：按 world_id 和关联对象读取相关记忆及近期剧情；保存本次使用的记忆版本。没有记忆时可以继续。
4. 主题设定：Qwen 选择现实动作对应的幻想行动，明确持续目标、必要世界规则与边界。
5. 片段脚本：Qwen 根据主题、事件和记忆生成目标一致的连续第一人称行动；无反转，不强制结束整场事件。
6. 视觉风格：Qwen 根据完整脚本选择本片视觉方案。
7. 分镜与声音方案：Qwen 拆分剧情并落实风格；记录镜头起止状态、时长、衔接和音效时机。
8. 本地格式处理：程序校验引用、四项结构、时长与连续状态契约，不调用Qwen做语义复核。保存四个创作阶段的结果；修改规则后创建新任务，保留旧版本。
9. 组装视频请求：程序将行动目标、前镜进展、当前关联脚本段落、风格、幻想规则、四项分镜和本镜起止动作范围组合为提示词，不传入后续脚本段落。
10. 顺序生成镜头：提交 WanVideo 异步任务，保存 task_id，轮询结果，下载成功片段。前段按目标时长裁切并统一30fps后提取实际末帧，再提交后段图生视频。记录前段版本与末帧校验值。
11. 技术检查：检查文件存在且可解码、时长、尺寸及帧率等，不判断画面是否符合剧情。
12. 音频准备：按声音方案取得背景音乐和音效。来源暂未指定，保留接口。未配置时进入等待音频状态；可保留无声预览，但不将其标记为正式完成。
13. 合成：验证片段依赖、按镜头顺序直接拼接已归一化片段、铺设音乐与音效。关闭生成片段原有音轨，只混入选定的音乐和音效。续接模式不再次重编码画面，确保用于后段输入的末帧仍是前段最后实际画面；不添加淡化或黑场。
14. 成片技术检查和归档：验证成片可播放、时长及输出规格，保存 manifest 和最终文件，标记完成。不声称做过媒体内容审核。
15. 记忆处理：保存新增世界设定草案；正式世界记忆的提交策略尚未确认，当前不自动提交。

音乐和音效不含人声由素材选择或生成约束保证；由于暂不检查媒体内容，不能宣称已自动验证音轨完全无人声。

## 4. 提示词与模型接口

### 故事接口

Qwen 的每个创作阶段均接收必要的事件、记忆、技能规则和上游结果，返回结构化结果。主题、脚本、视觉风格、分镜共四个阶段分别保存，无文本复核阶段。格式或内容结构校验失败时追加一次格式修正；网络错误不自动重发 POST，恢复任务会从最后成功阶段继续。checks保留为空数组，不作为模型自评报告。

技能原始故事输出遵循 `schema_version = "1.0"`，保留 theme、script、visual_style、audio_plan、shots、world_delta_draft、checks、issues 等字段。制作过程字段放在外层任务数据中，不修改技能的四项 prompt 契约。

### 视频接口

内部保存 JSON；实际请求把以下信息转成完整文本：

1. 统一视觉风格与稳定识别特征。
2. 当前镜头相关的幻想规则，落实为可见的因果变化。
3. 景别、构图、运镜手法、画面内容。
4. 持续行动目标、前镜进展、当前关联beat以及本镜起止动作范围；旧故事无action_goal时使用statement。

Qwen 在分镜阶段完成创作转译，程序组装阶段不新增情节。每镜独立携带必要风格，不使用“同上”。模板处理重复描述；冲突或超出长度限制时退回分镜修订，不静默截断关键内容。

组装结果单独存为 video_request.json，包含 prompt、参数和模板版本；认证头不保存。首段使用明确画幅、时长、分辨率参数。后段使用同一模型，传入前段末帧并设 ratio=adaptive，内部仍保留目标画幅用于技术检查。图片以 Base64 临时组装发送，归档仅存本地路径和校验值。统一设置 audio=false、prompt_extend=false，保持独立音频制作与已编写的分镜。四项分镜之外另存 continuity.start/end 六项状态，相邻边界须逐字段相同。

### 服务能力

| 能力 | 实现计划 | 配置 |

| 故事生成 | 百炼 OpenAI 兼容聊天接口 | qwen3.8-max |
| 视频提交与查询 | 百炼异步视频接口 | 首段 wan3.0-video-prime，后段 wan3.0-video-prime |
| 背景音乐 | 已实现本地素材文件适配器 | 生成服务未确定 |

Qwen 与旧视频模型已有真实样片记录；wan3.0-video-prime 已完成接口适配与本地测试，本次切换尚未提交真实生成任务。首帧续接的实现和验证边界见 [连续性要求](continuity.md) 与验证记录。

## 5. 任务与镜头状态

任务主要状态：created → preparing → story_generating → story_ready → video_generating → awaiting_audio / composing → completed。

异常或等待状态：wait_for_material、needs_resolution、awaiting_review、submission_unknown、failed。

镜头状态：pending → submitting → submitted → running → succeeded；另设 failed、submission_unknown。每个镜头独立保存生成尝试与远端任务 ID。

- 创作修改通过新任务保留旧版本，不允许更改提示词后继续混用旧镜头。
- 已拿到远端 task_id 时查询原任务，不重复提交。
- 提交超时且没有收到 task_id 时标记 submission_unknown，不盲目重发可能已受理的付费任务。
- 查询、下载等可重试操作采用有限次数退避；鉴权错误和参数错误不循环重试。
- 已取得任务编号的片段默认5分钟仍PENDING/RUNNING时，最终确认查询后最多自动重提一次。提交时间与次数持久化；新尝试沿用提示词及前段末帧，旧远端任务保留并标记被替代，不自动取消。达到次数上限进入needs_resolution，恢复时可查询当前任务但不突破上限。默认render持续运行最多30分钟，退出后需恢复才能继续操作。
- 视频生成失败可重试，已成功镜头可显式重做；续接链中重做前段会同时使全部后续片段失效，前段之前的成功片段复用。
- 写文件先写临时文件再替换，状态提交在产物成功保存之后执行；恢复时核对产物与数据库记录。

续接链严格逐镜生成，不能并行生成依赖前段末帧的镜头。不开启无限重试。

## 6. 模块与拟定文件

主要文件已实现。原规划的独立 ports.py、recovery.py 暂未拆出：服务使用可替换的 Python 对象接口，恢复逻辑集中在 pipeline.py；媒体探测与剪辑集中在 media/ffmpeg.py。

| 目录 | 拟定文件 | 职责 |
| --- | --- | --- |
| domain | events.py、continuity.py、errors.py | 输入规范化、连续状态契约与领域错误 |
| application | pipeline.py、settings.py | 编排、恢复、配置加载 |
| story | generator.py、validation.py | 规则装载、分阶段创作、数据契约与文本检查 |
| prompts | video_compiler.py | 单镜提示词组装与版本化模板 |
| providers | http.py、qwen.py、wan.py、audio.py | 服务请求、响应转换与错误分类 |
| media | ffmpeg.py | 剪辑、混音与文件技术检查 |
| memory | repository.py | 读取相关记忆、保存增量草案 |
| storage | files.py、jobs_sqlite.py | 产物保存与任务状态 |

入口为 `daydreamer.py` → `src/daydreamer_agent/cli.py`。测试集中在提示词约束、状态恢复、重复提交防护和音轨时间线等实际风险。

## 7. 每次任务的存储结构

```text
data/
├── jobs.sqlite3
├── memory/<world_id>/
│   ├── versions/<version>.json
│   └── drafts/<run_id>.json
└── runs/<run_id>/
    ├── input/                 # 原始卡、规范化输入、记忆及配置快照
    ├── story/                 # 主题、脚本、风格、分镜、声音方案
    ├── shots/<shot_id>/
    │   └── attempts/<attempt_id>/
    │       ├── video_request.json
    │       ├── task.json      # 远端任务 ID、状态等，不含认证信息
    │       ├── clip.mp4
    │       ├── prepared.mp4   # 实际拼接使用的30fps片段
    │       └── tail.png       # 上述片段的末帧
    ├── audio/                 # 背景音乐与音效
    ├── composition/           # 时间线与可选预览
    ├── final/video.mp4
    ├── manifest.json          # 输入版本、已选镜头、文件校验值及输出索引
    └── logs/                  # 脱敏运行日志
```

技能版本与提示词模板版本写入任务 manifest。技能随项目保存快照，后续更新需明确记录，避免修改技能后无法解释旧任务的生成依据。

## 8. 配置边界与尚待确定的产品选择

密钥从运行时环境、项目 .env 或显式指定的密钥 CSV 读取到内存，配置样例不含真实密钥。禁止把密钥、认证头或完整环境变量快照写入运行档案。

时长、画幅、分辨率由每次任务确定，项目默认配置保持未指定。允许先完成创作；提交付费视频任务前必须解析为明确参数。创作阶段对已给出的单镜时长强制检查 3–15 秒整数约束。TOML 中空字符串被视为未指定。

共享世界与独立故事都由可选 world_id 支持，默认不虚构已有世界。第一版 plan 与 render 分开运行，显式执行 render 才提交视频；无需额外确认开关。记忆增量仅保留草案。

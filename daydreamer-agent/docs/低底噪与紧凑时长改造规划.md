# 低底噪与紧凑时长改造规划

日期：2026-10-02。状态：已在本地完成代码实施。223项自动化测试通过，未发起付费生成，未部署线上或修改历史任务。原规划与实施记录一并保留。

本规划在已完成的“视频提示词生成声音、最终合成保留原生音轨”基础上增加两项要求：减少无必要的持续环境噪音；优先生成15–30秒、内容紧凑的视频，只有动作与因果表达确实需要时才延长。

## 1. 总体原则

1. 声音以必要、清楚的动作音效为主；环境声低存在感、按场景需要出现，允许安静留白。
2. 音乐继续保持可选、克制，有明确的剧情进入与退出节点。不能用音乐填补删掉的环境噪音。
3. 15–30秒是自动创作的优先区间，不是固定30秒，也不是必须凑到15秒。
4. 紧凑来自有意义的动作、后果与合理时长，不靠堆叠事件、频繁切镜、机械倍速或截断动作实现。
5. 自动时长保留现有60秒硬上限。30秒以上属于有理由的例外，60秒不是创作目标。
6. 继续使用原有主题、脚本、风格、分镜规划、逐镜生成流程；不增加独立声音服务或模型评审阶段。

## 2. 当前代码与缺口

- `story/sound.py` 已要求音乐可选、动作音效同步，但“环境声优先”“声音延续”等表述没有限制持续底噪，可能诱导全程风声、引擎轰鸣或宽频沙沙声。
- `config/default.toml` 的自动模式只保存 `max_duration_seconds=60`，缺少优先15–30秒的配置。
- 脚本阶段已有不重复、不堆奇观的要求，但没有明确的默认时长预算。若先写成长脚本，后面的分镜又必须覆盖全部beat，就难以自然缩短。
- `story/timing.py` 会保留模型建议时长；缺少建议时默认按每镜6秒估算。建议总长超过上限时，会按比例重新分配秒数。这能保证数值合法，却不能保证动作表达仍然自然。
- 最终合成已经能够保留原生音轨；本轮重点是创作约束和时长规划，不是后期滤掉所有环境声。

## 3. 环境声策略

### 3.1 默认减少的声音

不因“更真实”“有氛围”“镜头需要连续”而自动添加或维持：

- 全片持续风噪、麦克风摩擦声、白噪声或宽频嘶声。
- 长时间交通底噪、引擎或机械低频轰鸣。
- 与动作没有关系的科幻嗡鸣、持续低频声垫、空泛混响。
- 多种持续环境声叠加，导致动作声不清楚。

这些不是禁止词。若剧情本身依赖强风、发动机运转或持续警报，可以保留；需要说明声源、必要区间、强弱变化及退出条件，而不是自动延续到全片。

### 3.2 优先保留的声音

- 关键动作的发生点及必要尾音：按铃、扣合、落地、撞击、短促摩擦、设备启动等。
- 帮助理解位置或因果的少量环境线索，例如进入室内后的短暂回声变化。
- 运动中必要而轻的持续声；只有在持续运动确实需要听觉表达时保留，不刻意逐次重击或夸大音量。

声音层次默认以关键动作音效最清楚；环境声和可选音乐处于辅助位置。关键声音结束后允许自然安静，不做强制绝对静音，也不逐镜突然切断合理尾音。

### 3.3 保持现有声音字段

不新增独立环境音轨或环境声生成模块，继续使用：

- `audio_plan.sound_motifs`：少量必要声源，不把“全程风声”等固定底噪当作必选项。
- `shot.audio.sfx`：在每条文字中说明声源、触发动作、持续范围和衰减；持续声尤其要明确必要性和退出点。
- `shot.audio.continuity`：仅延续需要跨镜的声音，不默认延续所有底声；动作尾音与环境变化保持自然。
- `shot.audio.music`：保留明确的无配乐选择和进入退出规则。

示例：骑行通过窄门时，保留按铃的一声、近距离短促轮胎摩擦，轻微滚动声仅在必要运动段出现；不铺满风噪、电机轰鸣或连续科幻嗡鸣，关键音效之间可以留白。

最终视频提示词追加“环境声克制”约束，避免分镜已经安排留白，视频模型又自行添加全程噪音。

## 4. 时长选择规则

| 情况 | 处理方式 |
| --- | --- |
| 自动时长，一般内容 | 从主题和脚本起按15–30秒组织；按动作需求选择具体秒数 |
| 不足15秒已经表达清楚 | 允许更短，遵守模型单镜限制；不补慢动作、停留或新事件凑时长 |
| 超过30秒 | 仅因必要动作、因果或空间过渡需要延长，并记录具体理由 |
| 超过60秒 | 超出当前自动模式硬上限，在现有有上限的修正流程中重新安排；不能直接截断或机械压缩 |
| 用户显式指定总时长 | 在模型和项目上限内优先遵守，例如12秒或40秒；仍要求内容紧凑 |
| 用户选择single_take | 遵守当前单次最多15秒的能力限制，不暗中切换为多段模式 |
| 恢复已有任务 | 使用原任务冻结策略，不能自动把历史片段裁成新长度 |

超过30秒的有效理由，例如：“绕过障碍、进入侧道、完成一次接近需要连续呈现，压到30秒会遗漏转向后的关键反应。”

无效理由包括：“更有电影感”“音乐还没结束”“画面很好看”“需要凑满镜头数”。这些作为创作指令中的判断标准，不用关键词黑名单假装自动理解剧情。

## 5. 各阶段如何落实

### 5.1 输入与主题

新任务在配置快照和规范化制作约束中保存优先时长区间、硬上限、策略版本及是否有显式总时长。命令行、事件卡、原视频入口和网页任务使用一致的默认策略；显式参数按现有优先级覆盖。

主题优先选择在15–30秒内能清楚呈现的一段行动，尽快进入正在发生的事情，不先安排无意义的出发、看景或背景介绍。仍允许事情在片段结束后继续。

### 5.2 脚本

在脚本首次生成时加入紧凑要求，而不是分镜完成后再删内容：

- 每个beat推进位置、目标关系、障碍、决定或结果中的至少一项。
- 合并重复观察、重复接近、没有新后果的向前移动。
- 保留观众理解动作所需的建立、反应和转向时间；安静或停顿只要有叙事作用就可以保留。
- 不为达到时长或增加热闹程度添加新事件。
- 不按机械固定beat数量创作，不要求强制结尾高潮或收束整场事件。

### 5.3 分镜规划

根据已经紧凑的脚本安排镜头和整数秒数。保留自然动作边界，不均分镜头，不把15秒单镜上限当作每镜目标。

新版本规划结果增加一个内部 `timing_reason` 对象：

- `reason`：为什么这些动作需要所建议的时长。
- `extension_reason`：自动总长超过30秒时，说明压入优先区间会损失哪些必要过程；其他情况为空字符串。
- `extension_beat_ids`：延长理由对应的已有beat；其他情况为空数组。

该对象只属于内部规划与 `plan-timing.json`，不扩大对外故事包，也不改变四项画面prompt。超过30秒的自动方案必须有理由及合法引用；程序只检查结构和引用，不把这当作语义审查通过。

### 5.4 本地时长分配

对新策略任务：

1. 没有显式总时长时，优先采用合法、具体的动作时长建议；不自动凑到15、30或60秒。
2. 要求分镜规划给出明确时长，避免新增任务继续用“每镜缺省6秒”替代动作判断；旧任务继续支持原有null规则。
3. 31–60秒且缺少延长依据时，在原规划请求的有限格式修正路径中补正或重新规划，不新增常规评审请求。
4. 超过60秒或镜头数量与时长不可能兼容时，退回现有有限修正路径；不把长计划简单按比例压到60秒。
5. 自动模式保留合法建议，不自动拉长或加速；显式固定总时长继续兼容现有整数配平，脚本与分镜事先按该预算创作。
6. 修正次数及创作重开上限沿用现有规则，恢复不重置次数。修正用尽不能提交不符合约束的视频。

### 5.5 逐镜声音与最终提示词

最终秒数确定后，再按实际镜头时长生成画面和声音文字，避免音效描述沿用已失效的时间点。优先用动作作为声音触发条件，秒数作辅助。

视频提示词同时包含：本镜明确的动作范围、自然紧凑的节奏、禁止无意义停留或重演、必要音效、低存在感环境声，以及可选配乐。镜头之间仍以真实末帧续接，不用高频切镜替代剧情推进。

## 7. 兼容与恢复

- 当前声音v1和旧时长策略保留；新声音v2与节奏v1只用于新任务。
- 不能直接覆盖v1共享常量，再让所有非零版本使用新常量，否则已保存指令摘要可能不匹配。
- 缺少新版本字段的旧任务按旧策略恢复，旧schema和缺省时长行为保持可用。
- 旧故事包导入仍可使用原字段，不强制补写内部时长理由。是否按新规则重新创作，通过新建任务表达；单纯重新合成不会改变已有画面或环境声音。
- 本次不批量更新历史任务、重新提交片段或覆盖历史成片。

## 8. 验证与验收

### 工程验证

1. 自动方案18、24、29秒均保持原长，不补满30秒；12秒合理方案不被拉长到15秒。
2. 自动36秒有延长理由及有效beat引用可接受；无理由时进入有上限的现有修正路径。
3. 超过60秒不直接比例压缩；镜头最短时长、单镜15秒上限与single_take限制继续有效。
4. 显式12秒或40秒按指定总长处理，不被默认区间覆盖。
5. 新模式要求具体时长；旧null分镜、旧配置、旧故事检查点仍能恢复。
6. 新规则进入脚本、分镜与最终视频提示词；无配乐与环境留白不被全片方向覆盖。
7. 继续运行原生声音保留、manual/off、视频恢复与网页交付测试。正常成功路径不增加独立模型请求。

重点扩展 `tests/test_story_timing.py`、`tests/test_seeded.py`、`tests/test_native_audio.py`、`tests/test_workflow.py`、`tests/test_video_workflow.py`，并新增少量默认策略与版本选择测试。

### 实际样片验收

- 骑行或步行：15–30秒，以少量关键动作声为主，检查风噪和滚动声是否持续抢占听感。
- 机械装置互动：启动、扣合和反馈清楚，未活动时不自动铺满机械嗡鸣。
- 有必要持续声的场景：保留剧情所需声源，不因低底噪原则破坏环境可信度。
- 确需超过30秒的连续行动：核对延长部分是否有实际进展，去掉后是否损伤理解。

提示词和数值测试不能证明真实画面紧凑或噪音降低；这些由实际生成后的观看、试听确认，不新增自动内容评分和模型复核。

## 9. 实施顺序

1. 先完成共享规则、配置版本和入口冻结，保证新旧任务分流明确。
2. 再接通主题/脚本预算、分镜时长依据和新自动分配规则。
3. 同步低底噪提示词、示例及交付说明。
4. 完成离线回归与既有真实FFmpeg测试，再以实际新样片检验创作效果。

完成后，默认体验应是：短时间内清楚推进一段行动，声音干净、有必要的细节和留白；音乐和更长时长都由内容需要决定。

## 10. 实施与验证记录

- 声音v2增加低存在感环境声、持续声必要区间、自然留白及跨镜尾音约束；原生声音保留算法未改变。
- 节奏v1将预算传入主题、脚本、规划和逐镜阶段。run/plan及原视频入口冻结15–30秒优先区间和60秒上限；网页复用相同入口。
- 新内部规划schema要求具体镜头秒数及timing_reason。合法自动方案保持原长，超过优先区间须有理由与合法引用；超过硬上限进入现有有上限的修正流程，不机械压缩。
- 模板2.3增加最终视频的节奏与环境声约束；原声音v1与无节奏策略继续原文本、旧schema和2.2编译行为。合成记录从已保存请求读取模板版本，不将旧任务错误标记成新模板。
- 时长依据在阶段plan-timing.json及story/timing.json记录，后者关联故事摘要。导出增加时长规划.json，可读分镜展示时长与延长原因；公共故事包和四项画面字段不变。
- 223项回归通过；新增16项覆盖短片不凑长、延长理由、超上限有限修正、不增加常规生成阶段、旧版本恢复、显式时长、原视频理解中断后的策略冻结及导出。另对最终模板版本记录补测15项紧凑策略测试，全部通过。
- 真实FFmpeg的原生声音保留和时间位置测试继续通过；未生成新的付费样片，持续噪音与实际画面节奏效果仍需观看、试听确认。

# 白日梦想家 · 风格转译

把用户亲历的平凡生活发展为有趣、新颖、能辨认现实来源的连续幻想剧情。输入和输出都是第一人称片段。执行顺序为：生活事件与故事记忆 → 明确行动目标与必要世界规则 → 连续片段脚本 → 按情节选择视觉风格 → 按动作拆分分镜 → 直接交付。所有约束在创作时落实，不增设生成后的内容审阅、核查、评分或修订轮次。

## 输入与边界

接收生活事件卡、可用的故事记忆和制作约束。具体字段及输出格式见 [references/input-output-schema.md](references/input-output-schema.md)，正式交付前读取。

- 生活事件卡是事实依据；不修改原卡，不把幻想写回现实记录。只依据实际可读取的信息，不假装看过未提供或不可访问的关键帧。
- 记忆用于读取世界规则、已有剧情、人物关系、地点和物件状态，并检查近期重复套路。不要从历史记忆提取、复制或默认沿用视觉风格，包括旧提示词中的画风、材质、色彩、光线和渲染方式。
- 分清叙事身份与画面表现：某把钥匙打开哪扇门属于连续性信息；旧画面如何绘制钥匙不决定本次风格。保留识别或解谜必需的标志、空间关系及因果功能。
- 记忆缺失不等于素材不足。可基于事件提出本次片段的局部幻想规则，标注为候选，不虚构既有历史。记忆相互矛盾且影响剧情时，返回冲突项。
- 用户当前明确提出的风格偏好在非写实范围内采用；输入若含写实倾向，保留其情绪、配色或叙事意图，转为明确的非写实表现，并说明调整。不要将历史偏好自动当作本次要求。未知时长、画幅或模型不阻止创作，不假称采用了已确认的制作规格。
- 只交付创作结果。媒体生成、音乐音效制作、拼接、储存和正式世界记忆提交由下游执行；不调用这些服务，不声称已经生成短片。

## 1. 从现实动作选择幻想行动

识别事件中最有辨识度的动作、物件、空间、光影或声音，为每个采用的细节保留事件引用。安静、重复、微小的日常也能成为入口，不要求强动作或剧烈情绪。

直接生成一个适合现实动作和空间的行动情境，不输出候选列表。骑行可以成为街头追逐，躲避与抬手可以发展为外星交战，穿行可以成为机关通道探索；这些只是方向，不将所有日常强制变成战斗。第一人称亲身参与同一任务，趣味来自行动中的应对和后果。

允许改变物件功能、空间尺度、世界规则和行动结果，在真实动作之后继续发展虚构情节。保持可辨认的现实入口和关键动作关系，无需逐帧复刻原视频。未拍到的现实过程和未知原因仍是未知；新增行为、动机与结果仅属于幻想。

让物件与空间参与行动：石墩可以要求绕行，停放车辆可以形成遮挡，车铃可以发出信号。不必把每个现实元素都变成魔法物件。不要仅换材质、加发光、改地名，或用不断前进加环境变形代替剧情。禁止安排反转、突然揭晓身份、梦醒或结尾另起一件事。

## 2. 设定统一主题

产出一句话主题、持续行动目标 action_goal、核心幻想规则、连续行动发展方向和主题边界。主题说明“我正在对谁或什么做什么”，如“我骑车穿过机械街区追赶携带包裹的信使”；不能只有“机械城市”或“石墩航道”等景观名称。此时不预先套用视觉画风。

- 一个片段围绕一个主要奇想展开，场景、物件、行动和结果共同发展该奇想。
- 行动变化来自前一步后果或已建立的场景规则，围绕同一目标推进；不在追逐中无故停下来观赏奇观或换成另一项任务。
- 可以发展多个相关细节，但不要把候选奇想拼接成一个片段。主题边界要具体说明本次围绕什么展开、哪些无关方向不加入。
- 与历史世界规则冲突时，优先改写奇想；不要以“需要新颖性”为由覆盖正式设定。

### 世界规则与可理解空间

只声明本次行动确实用到的少量幻想能力，说明作用对象、触发条件、可见作用和边界。未声明的部分遵守常识：物体需要支撑，移动要有路径，碰撞会受阻，载具需要承载与推进方式。无需解释魔法的科学原理，但不能临时追加能力掩盖动作断裂。

比喻不是运行规则：“车辆像峡谷”不能推出无支撑地垂直堆车；“车筐像船头”不能让自行车直接在水上航行。若确实发生功能转换，必须在可用时长内呈现必要结构和过程；否则采用更简单、可理解的行动。纸艺、卡通等美术表现不赋予随意替换场景的能力。

## 3. 编写第一人称片段脚本

按发生顺序描述我看见什么、我做什么、眼前发生什么变化，以及结束时的状态。用可见动作和可听环境变化表达故事，不靠设定说明、解释字幕、旁白或对白才能理解。

先写一段在同一时空内持续发生的行动，再划分 beat，不先凑镜头数量。各 beat 依次承接“当前处境 → 我的应对 → 可见后果 → 下一步行动”，例如锁定目标、接近、跟随转弯、避开障碍、继续紧追；不要把这一关系套成每镜一套完整故事。

不套起承转合、不安排反转，不要求短片结束整场追逐或交战。可以从行动进行中开始，停在自然动作节点，如完成转弯后重新对准目标。完整的是本段动作关系，任务仍可继续。不要突然黑场、目标消失或以音乐淡出代替动作承接。

first_person_action 写具体行动，visible_change 写该行动或已建立规则产生的后果，end_state 同时保留当前位置、目标/障碍状态和待继续的行动。后续 beat 继承这些进展，不重新发现目标、不重做已完成的动作。写在视野外的事件只能作为可听线索，或先通过转头、合理反射建立可见性。

摄像机始终代表经历者的眼睛。可以出现自己的手、持有物、低头看到的身体局部，以及环境中的他人；不要求主角完整外观作为输入，不编造用户的现实外貌。

禁止第三人称跟拍、展示自身全身的外部机位、无人机俯瞰、切到他人视角或脱离身体位置的全知镜头。若故事涉及飞行或身体变化，先在情节中建立原因，镜头仍随经历者所在位置连续移动。

## 4. 根据完整情节选择视觉风格

完成脚本后读取 [references/style-selection.md](references/style-selection.md)，按本次空间、动作、节奏、情绪和核心奇想选定视觉方案，并说明选择理由。不要为了视觉效果反向塞入不相关剧情。

**转译结果必须明确非写实，禁止写实、微写实、半写实、照片级真实、真人实拍感及其混合画风。** 从适合情节的手绘、二维动画、绘本、剪纸、风格化黏土或非写实三维动画等表现中选择，不固定单一画风。第一人称表示视点位置，不意味着真实摄影；保留现实细节依靠动作、轮廓、空间关系与物件功能，不复刻摄影质感。

限制覆盖全片所有镜头、过渡、环境、人物、可见的手和身体局部。不得用写实开场再转动画，也不得在动画环境中混入写实双手或物件。真实生活视频仍可作为输入依据，不能因其写实质感而直接继承到幻想片段。

非写实不等于抽象化或取消空间关系。保留清楚的物体轮廓、体积、前后遮挡、支撑及可通行路径；即使选择二维或剪纸，也要让用户看懂目标在哪里、动作如何作用。不要默认“完全扁平化”“无立体透视”或把物件极度简化到无法识别。

统一片段内的画面媒介、造型、色彩、材质、光线与运动表现。必要的风格变化须由情节引发并设计过渡；不逐镜随机换风格。背景音乐和音效也要服务同一主题与情绪发展。

## 5. 产出第一人称分镜提示词

每镜提示词严格采用四项：**景别、构图、运镜手法、画面内容**。编号、脚本对应、时长建议、衔接状态、素材引用及声音安排放在提示词之外的附属字段。

- **景别**：眼前场景或对象的观看范围；可以是环境全景或物件近景，不出现外部视角的主角全景。
- **构图**：视野中对象的位置、空间纵深、遮挡关系和手或持有物的可见位置。
- **运镜手法**：对应行走、转头、低头、抬头、探身或停步等视点运动，交代方向与停止位置。避免没有身体行动依据的环绕自己、反打自己或独立轨道运动。
- **画面内容**：明确第一人称，写出主体、环境、可见行动、幻想变化及本次选择的非写实视觉表现。每镜写明可见的风格特征（如简化轮廓、手绘色块或夸张比例），并注明“全画面统一非写实，无写实或微写实元素”；不把写实相关词作为正向风格标签。动作按顺序可执行，避免单镜塞入过多转折。每镜携带必要的稳定风格与身份特征，不能只写“同上”。

按动作边界分配时长，合并可连续完成的 beat，不平均切分、不为凑时长堆入变化。遵守本次模型的时长限制，镜头数量服从行动表达。相邻镜头延续同一时空、行动目标、视线、位置、手与持有物、障碍状态；单个 beat 跨镜时明确各镜分别完成哪一步。允许有动机的转弯、减速、停车和加速，不要求全程匀速向前。

若输出 continuity，object_states 同时记录行动进展，start/end 是与四项提示词一致的状态。没有明确输入要求时使用清楚的相对位置，不随意编写精确米数和速度而制造时间矛盾。不用跳时空、物件瞬移或背景替换掩盖缺失过程。

整片仅使用背景音乐和音效；音乐不含演唱或人声采样，无旁白、人物对白或原始人声音轨。源素材语音只作为理解依据。声音可以分配在各镜头并注明跨镜延续，供下游制作与拼接。

## 6. 直接交付

按接口规范交付主题、连续行动脚本、视觉方案及理由、分镜和声音方案。保留 checks 字段用于兼容接口，固定输出空数组；不生成审阅报告或自评 pass，不发起额外核查或改写调用。字段、引用和时长等本地格式校验由 Agent 保留，不代表内容已审阅。

素材不足时返回待积累及原因；关键输入或记忆冲突时返回具体冲突，不静默覆盖。这是创作输入处理，不是生成后的核查环节。

确有新增设定时才附世界增量草案，不自动提交。不声称生成视频已经验证或必然连续。输出是否符合剧情仍取决于后续模型执行，本 skill 不新增结果检查。

需要完整示例或边界案例时读取 [references/examples.md](references/examples.md)。示例仅演示方法，不作为固定画风或默认故事模板。

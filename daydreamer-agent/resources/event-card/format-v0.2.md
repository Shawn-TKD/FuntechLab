# 白日梦想家 · 生活事件卡 JSON 结构

版本：v0.2｜整理日期：2026年9月22日

依据：用户最新修订的七项生活事件卡结构。七项内容按本次修订整理；英文字段名、嵌套结构及存取规则为实现建议。

## 1. 定义与文件组织

生活事件卡是对一件真实生活事件的结构化记录，也是故事生成的输入。卡片应简短，但能说明“发生了什么、依据在哪里、哪些细节值得保留”。

建议每张卡保存为一个 UTF-8 编码的 JSON 文件，文件名为 `<event_id>.json`。一张卡对应一件事件，可以关联一个或多个原始素材。

配套文件：

- [生活事件卡_模板.json](./template.json)：用于填写的空模板，不能直接作为有效事件投入生成。
- [生活事件卡_示例.json](./example.json)：虚构的填写示例。素材ID、片段时间和内容均为演示数据，图片地址留空，没有关联真实素材。

JSON 内保存文字、素材标识和媒体引用。图片、视频与音频独立储存，通过引用读取，不直接嵌入 JSON。

## 2. 七项结构

| 组成 | JSON 字段 | 内容与作用 |
| --- | --- | --- |
| 基本信息 | `basic_info` | 事件ID、简短标题、发生时间或时间范围、场景；标识事件并建立时间顺序。场景字段简短说明在什么情境下发生了什么，不罗列环境中的物件。 |
| 事件描述 | `event_description` | 一句话概览及按顺序记录的动作与场景变化，说明实际发生了什么。 |
| 关键画面 | `key_frames` | 场景图、关键动作及额外描述，明确可参考的场景、空间结构、构图或动作，为幻想片段提供现实骨架。 |
| 声音信息 | `audio_info` | 有用的环境声、动作声音、可用语音转写；无音频时为空数组，补充事件理解及有用细节。 |
| 值得保留的细节 | `details_to_preserve` | 有辨识度的物件、空间关系、动作、光影或声音，建立现实与奇幻故事之间的联系。 |
| 筛选信息 | `selection_info` | 入选理由、是否重复、待生成或待积累状态，支持自动取舍与后续积累。 |
| 记忆关联 | `memory_links` | 关联既有角色、地点或物件记录ID；无关联时使用空数组，为连载检索提供入口。 |

## 3. 字段说明

### 3.1 基本信息 `basic_info`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `event_id` | 字符串 | 事件唯一标识；正式保存时非空，更新同一事件时保持不变。 |
| `title` | 字符串 | 简短概括发生了什么，例如“在亮灯的店门前短暂停留”。 |
| `time_range.start` | 字符串或 null | 事件开始时间，使用带时区的 ISO 8601 格式；未知则为 null。 |
| `time_range.end` | 字符串或 null | 事件结束时间；未知则为 null。仅有一个时间点时可只填写 start。 |
| `scene` | 字符串 | 简短的事件情境，例如“经过小巷，在店门前短暂停留。”避免扩写场景陈设。 |

### 3.2 事件描述 `event_description`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `summary` | 字符串 | 一句话概览真实发生的事情。 |
| `sequence` | 数组 | 按时间顺序记录动作与场景变化；没有可辨认的变化时可为空，不补造动作。 |
| `sequence[].order` | 整数 | 从1开始的顺序号，在当前卡片内唯一并递增。 |
| `sequence[].description` | 字符串 | 该步骤中可观察到的动作或变化。 |
| `sequence[].source_refs` | 数组 | 支撑该步骤的来源素材及片段位置，可关联多段素材。 |

基本信息用于快速识别；事件描述负责展开经过。二者都应简短，不重复堆砌环境细节。

### 3.3 关键画面 `key_frames`

每项对应一张图片及其参考说明。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `frame_id` | 字符串 | 当前卡片内唯一的关键画面标识。 |
| `image_uri` | 字符串或 null | 系统可以解析的图片地址或存储路径；尚未提取图片时为 null。 |
| `material_id` | 字符串 | 关键画面来自哪个原始素材。 |
| `timestamp_seconds` | 数字 | 关键帧在该素材内的位置，单位为秒。 |
| `description` | 字符串 | 客观描述画面中的场景或关键动作。 |
| `reference_focus` | 字符串数组 | 生成时建议参考的场景、空间结构、构图或动作。 |

例如，description 记录“镜头停在店门前，暖色灯光从门内透出”；reference_focus 记录“门与周围环境的明暗关系”“门前短暂停留的动作”。具体奇幻改编保存在后续转译结果中。

### 3.4 声音信息 `audio_info`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `audio_id` | 字符串 | 当前卡片内唯一的声音线索标识。 |
| `type` | 字符串 | environment（环境声）、action（动作声音）或 speech（语音）。 |
| `description` | 字符串 | 简短说明听到了什么。 |
| `transcript` | 字符串或 null | 可用语音的转写；非语音或没有可用转写时为 null。 |
| `source_refs` | 数组 | 对应素材及声音所在片段位置。 |

无有效声音信息时使用 `[]`。声音用于理解事件；成片仍遵循PRD中仅使用背景音乐和音效的要求。

### 3.5 值得保留的细节 `details_to_preserve`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `description` | 字符串 | 值得保留的具体特征。 |
| `value` | 字符串 | 该特征为何有助于连接现实与奇幻故事。 |
| `frame_ids` | 字符串数组 | 引用本卡中的关键画面，无则为空数组。 |
| `audio_ids` | 字符串数组 | 引用本卡中的声音线索，无则为空数组。 |
| `sequence_orders` | 整数数组 | 引用本卡中的事件步骤，无则为空数组。 |

关键画面说明单张画面如何参考；值得保留的细节提取整件事件的重点，可以跨画面、声音和动作步骤。每条细节应至少关联一项依据。

### 3.6 筛选信息 `selection_info`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `reason` | 字符串 | 入选或待积累的简短理由。 |
| `is_duplicate` | 布尔值或 null | true 表示重复，false 表示已判断为不重复，null 表示尚未判断。 |
| `duplicate_of_event_id` | 字符串或 null | 重复时指向对应事件ID；不重复或未判断时为 null。 |
| `status` | 字符串 | waiting_accumulation（待积累）或 waiting_generation（待生成）。 |

本版只定义用户提出的两种筛选状态。生成中、生成成功、生成失败等执行状态由PRD中的生成任务对象管理，不混入筛选状态。

### 3.7 记忆关联 `memory_links`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `character_ids` | 字符串数组 | 可关联的既有角色记录ID。 |
| `location_ids` | 字符串数组 | 可关联的既有地点记录ID。 |
| `object_ids` | 字符串数组 | 可关联的既有物件记录ID。 |

ID应能定位到已有记忆记录，由记忆系统提供其所属世界与具体内容。无可靠关联时留空，不临时编造ID，不将幻想设定写入真实事件描述。

### 3.8 共用素材引用 `source_refs`

每条引用包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `material_id` | 字符串 | 原始素材ID，由素材记录定位实际文件。 |
| `start_seconds` | 数字 | 片段开始位置，相对于该素材开头，单位为秒。 |
| `end_seconds` | 数字 | 片段结束位置，相对于该素材开头，单位为秒。 |

时间位置应满足 `0 ≤ start_seconds < end_seconds ≤ 素材时长`。它们与 basic_info 中的实际发生时间分别记录，不混用。跨素材事件通过多条引用表达；中间未拍到的过程不补写成事实。

## 4. 储存与调用约定

1. **创建：**素材理解与筛选流程按照模板填充七项字段。
2. **检查：**检查JSON能否解析、字段类型是否正确、事件ID与描述是否非空、时间范围是否有效、素材和卡内引用是否存在。空模板不能直接进入生成。
3. **保存：**以 `<event_id>.json` 保存卡片；同一事件补充内容时更新原卡，避免建立多个重复事件。
4. **读取：**后续流程依据事件ID读取并解析JSON，根据素材ID或图片地址获取需要的媒体，根据记忆ID读取对应设定。只有JSON文本不等于已经向模型传入图片和音频。
5. **筛选：**筛选状态为 waiting_generation、已完成去重且不存在重复的卡片进入生成候选；仍待积累的卡片继续保留。真正使用图片前应确认地址存在且可读取。
6. **生成：**将事件内容、关键画面及其参考说明、声音线索、保留细节与检索到的记忆一起交给风格化流程。
7. **回存：**故事和短片另行保存，并通过事件ID关联原卡。使用生成任务记录防止同一卡片被重复调度；幻想结果不覆盖真实事件描述。

JSON使用固定字段名，描述内容使用中文。缺失单个值用 null，空集合用 []；不使用字符串“null”或“无”代替空值。不确定的原因、心理或未拍到的经过不作为事实填写。

本文与配套JSON定义数据交接格式，尚未接入实际存储服务、素材检索或故事生成程序。

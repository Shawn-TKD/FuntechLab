# 心跳触发相机 · 方案架构（华为 Watch Fit 4 + Insta360 GO Ultra）

> 目标：HR 源 = 华为 Watch Fit 4 实时测心率；HR ≥ 110 自动开录 GO Ultra，回落自动暂停；控制器 = 安卓手机（同时收心率 + 控相机）；相机 = Insta360 GO Ultra（复用已下载安卓 SDK 2.1.5）。
> 本方案可作为黑客松"双世界"demo 的实时采集触发插件。

---

## 1. 华为 Watch Fit 4 能力边界（已查证，关键！）

Watch Fit 4（2025-05 发布）= **HarmonyOS 5.0（华为终端鸿蒙智能设备操作系统软件 V5.0）**，不是老款 LiteOS 手环。关键事实：

- ✅ 能装"轻量级穿戴应用"（Lite Wearable，JS / ArkUI.Lite 框架）；Fit 系列在官方 Lite Wearable 支持列表内。
- ✅ 手表端可用 `@system.sensor` 的 `sensor.subscribe({type:'heartrate'})` 读心率（官方 Lite Wearable 文档示例明确支持）。
- ❌ **无 WLAN（无 WiFi）**，只有蓝牙 5.2 + 蓝牙通话 → 手表→手机只能走蓝牙（BLE 或分布式软总线）。
- ❌ **手机侧官方 SDK 读 Fit 4 实时心率被权限墙卡死**：
  - **Wear Engine Kit** 的"人体传感器 HEALTH_SENSOR（含 ECG / PPG / HR）"权限**仅限专业研究机构**；个人开发者只能申请"设备基础信息 + 消息通知"两个基本权限 → 手机侧用官方 SDK 实时拿心率，**个人开发者基本走不通**。
  - **Health Service Kit** 的 `startReadingHeartRate`（约 5 秒/次）需申请 `HEALTHKIT_EXTEND_REALTIME_HEART_READ` 权限 + 审核 + 用户授权，且依赖"华为运动健康 App 已在后台同步设备实时数据" → 对"HR 到 110 立刻开录"的**硬实时不可靠**，同样要过审核。

**结论**：个人开发者想用 Fit 4 做实时触发，唯一能落地的路是 **自己给 Fit 4 写个轻量手表 App 读心率，再经 BLE / 分布式发给手机**（下面路线 A'）。其余官方 SDK 路径都被权限 / 延迟挡住。

## 2. 三条路径（针对 Fit 4 重新审视）

| 路线 | 做法 | 实时性 | 开发量 | 落地可行性（个人开发者） |
|---|---|---|---|---|
| **A'. Fit 4 手表 App 自读自发** | 手表 Lite Wearable App 读 `sensor.subscribe(heartrate)` → BLE / 分布式发给手机 | 秒级 | 中（DevEco + 华为开发者账号实名 + Fit 4 实机装调试包 + 手表→手机传输） | 可行但要过华为开发者账号 / 签名 / 实机调试门槛 |
| **B. 加标准 BLE 心率胸带** | Polar H10 / Coospo 等原生广播 GATT 心率服务 `0x180D` / 特征 `0x2A37`，手机直接 BLE 订阅 | 秒级 | 低（零华为开发、零审核） | ★★★★★ 最稳最省，黑客松 30h 内首选 |
| **C. 官方 SDK（Wear Engine / Health Kit）** | 手机侧实时读 Fit 4 心率 | 卡权限 / 5 秒延迟 | 低-中 | ✗ 个人开发者被权限墙挡，排除 |

## 3. 推荐架构（默认路线 B，A' 为可选升级）

### 3.1 组件
- **HR 源**：路线 B = BLE 心率胸带（或路线 A' = Fit 4 手表 App）。
- **控制器**：安卓手机，前台 Service：BLE 订阅心率 + 阈值判定 + 调 GO Ultra SDK。
- **相机**：Insta360 GO Ultra。

### 3.2 数据流
```
[心率源] --BLE/蓝牙(~1Hz)--> [手机 Controller: 接收 → 阈值引擎 → GO Ultra SDK]
                                                  | HR≥110 开 / HR<100 停（迟滞）
[Insta360 GO Ultra] <--WiFi(BLE引导切换)-- startCapture()/stopCapture()
```
- 手机**同时** BLE 收心率 + WiFi 控 GO Ultra，两无线互不冲突、运行时不依赖公网。
- 激活 GO Ultra（`activeCamera(appId, secretKey)`）走手机公网 `openapi.insta360.com`，一次性，连相机热点前用蜂窝做完即可。
- 若固执走 Health Kit（需公网），GO Ultra 不能连相机 WiFi 热点（会断网）→ 必须改 **USB** 连 GO Ultra。

## 4. 阈值逻辑（迟滞，防抖动）

```
state = PAUSED
on hr update:
    if state == PAUSED and hr >= 110:   startRecord(); state = REC
    if state == REC    and hr <  100:   stopRecord();  state = PAUSED
```
回差 10 拍（110 开 / 100 关）避免心率在阈值附近抖动导致疯狂开关。

## 6.5 路线 A'（Fit 4 手表 App）的真实门槛（已查证，务必先读）

选 A' 不等于"写个手表 App 就完事"，有三座大山：

1. **手表→安卓手机实时传输，唯一官方通道 = Wear Engine P2P 消息**。Lite Wearable 的 `@system.bluetooth` 只提供 BLE 扫描，**不能做 GATT Server 广播**，所以"手表做 BLE 外设发给安卓"在 Lite Wearable 框架里走不通。只能走 Wear Engine（华为私有通道，基于已配对蓝牙链路）。Wear Engine 手机侧 SDK 有 Android / iOS / HarmonyOS 三版，**安卓可用**——这是 A' 能成的技术前提。
2. **个人开发者权限模糊**：官方文档写"个人开发者当前只可申请设备基础信息、消息通知两个基本权限"，但开发者论坛明确说"**设备基础信息权限已覆盖双端通信的场景**"——即 P2P 消息可能只需基础权限即可调 `sendMessage / registerMessageReceiver`。**需实测/申请确认**，存在被卡风险。
3. **调试安装需华为手机中转**：Lite Wearable App 推到 Fit 4，官方流程依赖"**华为手机（HarmonyOS 5 之前版本）+ DevEco Assistant + 华为运动健康 App**"手动拷贝 HAP 到 `/sdcard/haps/` 再安装。**你的 Redmi 安卓做不了调试机**，需借/备一台华为手机。

合计前置：华为开发者账号（实名）+ 一台华为调试手机 + DevEco Studio + Wear Engine 权限（基础或通信）。**对黑客松 30h 窗口，这三步可能爬不完**——若卡住，立即退回路线 B（胸带），手机端代码（阈值 + GO Ultra 控制）完全复用。

## 6.6 路线 B 自制版（开发板自制 BLE 心率广播器，当前最现实）

用户反馈：想要标准 BLE 胸带（路线 B）但暂无该设备，**手头有硬件开发板**。→ 直接用开发板做一个广播标准 GATT 心率服务（`0x180D` / 特征 `0x2A37`）的 BLE peripheral，即可被手机端标准 BLE 订阅代码直接消费，**完全复用路线 B 的手机端**。

优势（对比 A'）：
- 绕开华为三座山（开发者账号 / 华为调试手机 / Wear Engine 权限审批）。
- 不用采购胸带。
- 手机端 `HRService.kt` 订阅 `0x2A37` 的代码不变。

分阶段落地（建议）：
- **阶段 1**：开发板先广播**模拟心率值**（含越过 110 的片段），先把"BLE 订阅 → 阈值 → GO Ultra 开停"端到端跑通（零外部依赖）。
- **阶段 2**：接真实心率传感器（MAX30102 光电 / PulseSensor / AD8232 电极胸带）替换模拟值。
